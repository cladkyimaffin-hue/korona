# AI-README.md

## Назначение файла

Этот файл является картой репозитория для искусственного интеллекта.

ИИ должен прочитать этот файл перед анализом любой задачи, связанной с
инфраструктурой, Proxmox VE, виртуальными машинами, Ceph, Windows Server,
1С, сетями, резервным копированием или документацией.

Файл не является набором команд для безусловного выполнения.
Он объясняет структуру знаний, порядок поиска информации и назначение
документации.

Обязательные операционные правила находятся в файле:

    AI-INSTRUCTIONS.md

Если правила этого файла противоречат AI-INSTRUCTIONS.md, приоритет имеет
AI-INSTRUCTIONS.md.

---

## 1. Назначение репозитория

Репозиторий содержит эксплуатационную документацию инфраструктуры:

- Proxmox VE;
- кластер Proxmox;
- узлы виртуализации;
- Ceph-хранилища;
- виртуальные машины;
- Windows Server;
- шаблоны Windows;
- серверы 1С;
- сетевые настройки;
- резервное копирование;
- устранение неисправностей;
- команды администрирования;
- исторические решения и инциденты.

Документы создаются не только для людей, но и для поиска ответов ИИ.
Поэтому ИИ должен сначала искать готовое решение в репозитории и только
после этого предлагать новую диагностику или изменение конфигурации.

---

## 2. Главная цель ИИ

ИИ должен помогать администратору:

1. быстро находить существующие решения;
2. не повторять уже отвергнутые варианты;
3. не путать похожие серверы, IP-адреса, VM ID и хранилища;
4. понимать зависимость между шаблонами, клонами, дисками и ВМ;
5. отличать подтверждённые факты от предположений;
6. предупреждать об опасных командах;
7. давать минимально необходимый и проверяемый набор действий;
8. сохранять историю решений в документации;
9. не менять рабочую инфраструктуру без подтверждения;
10. явно указывать, когда данных недостаточно.

## 3. Структура репозитория

Документы организованы по категориям — отдельная папка внутри `Proxmox/`
на каждую:

| Папка | Назначение |
|---|---|
| `00_Meta/` | Служебные файлы конвейера: `SCHEMA.md` (формат метаданных), `TAGS.md` (реестр тегов), `registry.csv` (реестр документов), `CHANGELOG.md`, `CONFLICTS.md`, `TEMPLATES/` |
| `00_Inbox/` | Необработанный сырой материал, ожидающий разбора конвейером |
| `01_Hardware/` | Оборудование серверов, коммутаторы, сетевые карты |
| `02_Installation/` | Первичная установка Proxmox VE и базовая настройка узлов |
| `03_Network/` | Сетевая конфигурация: bond, VLAN, веб-интерфейс |
| `04_Storage_Ceph/` | Хранилище Ceph: пулы, OSD, планирование дисков |
| `05_VirtualMachines/` | Виртуальные машины, шаблоны, клонирование, Windows Server, Active Directory |
| `06_Troubleshooting/` | Инциденты и их решения |
| `07_Vaultwarden/` | Сервер паролей Vaultwarden |
| `99_Archive/` | Устаревшие документы, помеченные `superseded_by` |

Корневые файлы `Proxmox/` (не в подпапках): `AI-README.md` (этот файл),
`AI-INSTRUCTIONS.md` (правила ИИ), `AI-environment_facts-korona-proxmox.md`
(факты об инфраструктуре), `INDEX.md` (навигация по документам).

**Точный список документов не хранится в этом файле.** Раньше здесь был
построчный перечень всех файлов с прямыми ссылками — он расходился с
реальностью при каждом переносе или переименовании документа (в частности,
здесь была ссылка на несуществующий файл и оборванный список категорий).
Актуальный список:

- `00_Meta/registry.csv` — машиночитаемый: `document_id`, категория, теги, статус;
- `Proxmox/INDEX.md` — человекочитаемая навигация, генерируется из `registry.csv`.

Протокол обработки и переноса документов — `AI-INSTRUCTIONS.md`, раздел 8а.

## 4. Приоритет источников

При ответе ИИ использует источники в следующем порядке:

1. текущая конфигурация системы, предоставленная пользователем;
2. свежий вывод команд с текущего сервера;
3. профильный документ конкретной ВМ или конкретной операции;
4. индекс соответствующего каталога;
5. документы общей инфраструктуры;
6. официальная документация производителя;
7. общие знания ИИ.

Если старый документ противоречит свежему выводу команды, приоритет имеет
свежий вывод команды.

Если два документа противоречат друг другу и невозможно определить, какой
новее, ИИ обязан:

- указать противоречие;
- привести оба варианта;
- не выбирать один вариант молча;
- запросить подтверждение или предложить безопасную проверку.

## 5. Как искать ответ

ИИ должен искать информацию в таком порядке:

### Шаг 1. Определить объект

Сначала определить:

- систему;
- узел;
- VM ID;
- имя ВМ;
- хранилище;
- операционную систему;
- роль сервера;
- тип проблемы.

Пример:

```text

Узел: pve01

ОС: Windows Server 2022

Роль: сервер приложений 1С
Проблема: раздел C: не расширяется
Шаг 2. Найти специальный документ
Если вопрос относится к VM 2001, сначала читать:

text

Шаг 3. Проверить связанные документы
После профильного документа проверить поля:

superseded_by.
Шаг 4. Использовать Quick Answers
Если в документе есть раздел Quick Answers, сначала использовать его для быстрого ответа.

Полный документ читать только если:

быстрый ответ недостаточен;
требуется выполнить операцию;

Шаг 5. Проверить команды

7. Ключевые технические правила
Full Clone
Для производственной ВМ использовать Full Clone.

Full Clone означает:

создаётся независимый диск;
ВМ не зависит от базового диска шаблона;
шаблон можно удалить после проверки клона;
изменения в шаблоне не изменяют уже созданную ВМ.
Нельзя автоматически предлагать Linked Clone для производственной ВМ, если пользователь явно не запросил такой вариант.

Изменение размера диска
Увеличение диска на уровне Proxmox не увеличивает раздел Windows автоматически.

Это две отдельные операции:

увеличить виртуальный диск в Proxmox;
расширить раздел и файловую систему внутри Windows.
Для VM 2001:

bash


qm resize 2001 scsi0 +924G
Нельзя использовать:

bash


qm resize 2001 scsi0 +924G --storage ceph-fast
Параметр --storage для этой команды не используется.

Recovery-раздел
Если Recovery-раздел находится сразу после раздела C:, Windows может не позволить расширить C: в свободное пространство.

Перед удалением Recovery-раздела нужно:

создать или проверить резервную копию;
определить точный диск;
определить точный номер раздела;
проверить размер раздела;
проверить, что это действительно Recovery;
получить подтверждение пользователя на удаление;
только после этого изменять разметку.
ИИ не должен предлагать удаление раздела по номеру без предварительного вывода Get-Disk и Get-Partition.

8. Быстрые маршруты поиска
Вопрос: «Как создавали VM 2001?»
Открыть:

text


Proxmox/Клонирование шаблона ВМ 2001 (Srv1c).md
Искать разделы:

«Тип клона»;
«Порядок развертывания»;
«Итоговая конфигурация»;
«Команды».
Вопрос: «Зависит ли VM 2001 от шаблона?»
Ответ искать в:

ai_summary;

dont_repeat;
разделе «Full Clone».
Краткий ответ: нет, использован Full Clone.

Вопрос: «Почему C: не расширяется?»
Открыть документ VM 2001 и искать:

Recovery;
Disk 0;
Get-Partition;
qm resize;
«расширение раздела».
Вопрос: «Какой диск у VM 2001?»
Искомые значения:

text


scsi0
VirtIO SCSI Single
ceph-fast
1 ТБ
Подтвердить командой:

bash


qm config 2001
Вопрос: «Можно ли удалить шаблон 2000?»
Можно только после проверки:

VM 2001 является Full Clone;
ВМ успешно запускается;
Windows загружается;
диск VM 2001 не является linked/base volume;
создана резервная копия;
шаблон больше не нужен другим ВМ.
9. Обязательные проверки перед ответом
Перед техническим ответом ИИ должен проверить:

о каком сервере идёт речь;
не перепутан ли VM ID;
не перепутан ли шаблон с клоном;
не перепутан ли узел;
не перепутано ли хранилище;
не является ли команда разрушительной;
есть ли актуальная резервная копия;
достаточно ли данных для безопасного вывода.
Если информации не хватает, ИИ должен не угадывать, а запросить конкретные данные, например:

bash


qm config 2001
qm status 2001
pvesm status
Для Windows:

powershell


Get-Disk
Get-Partition
Get-Volume
Get-Service QEMU-GA

11. Формат технической документации
Каждый эксплуатационный файл желательно строить так:

YAML-метаданные;
название операции;
назначение;
краткий ответ;
итоговая конфигурация;
пошаговая процедура;
команды;
контрольный список;
типовые ошибки;
опасные действия;
откат;
связанные документы;
дата следующего пересмотра.
Не помещать внутрь эксплуатационных документов блоки вида:

markdown


### USER
### SYSTEM
### ASSISTANT
Такие блоки смешивают технические данные с управляющими инструкциями и могут привести к неправильной интерпретации документа ИИ.

12. Принцип краткого поиска
Для экономии токенов ИИ должен использовать следующий алгоритм:

найти каталог по ключевому слову;
прочитать INDEX.md;
выбрать один наиболее подходящий файл;
прочитать YAML-поля;
проверить Quick Answers;
перейти к полному тексту только при необходимости;
прочитать dont_repeat перед предложением решения;
сформировать ответ с конкретными командами и проверками.
Не нужно читать весь репозиторий, если вопрос касается одной ВМ.

14. Основное правило
Репозиторий является источником накопленного опыта, но не заменяет проверку текущего состояния инфраструктуры.

ИИ должен использовать документацию для понимания:

что уже делали;
почему выбрали конкретное решение;
какие варианты отвергли;
какие команды применяли;
какие ошибки уже возникали.
Перед изменением production-инфраструктуры ИИ обязан отделять:

факт;
предположение;
рекомендацию;
команду проверки;
команду изменения;
опасную операцию;
действие отката.
