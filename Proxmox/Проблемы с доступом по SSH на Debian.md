### ASSISTANT
Ошибка **«Cannot assign requested address»** возникает ещё на стороне клиента — Windows даже не может начать подключение к такому адресу. И дело тут в самом адресе: **192.168.203.255 — это не адрес хоста**.

При маске /24 (255.255.255.0) адрес `.255` — это **широковещательный адрес** сети 192.168.203.0. Скорее всего, вы скопировали его из вывода Debian, перепутав поля:

```
inet 192.168.203.10/24 brd 192.168.203.255 scope global ens33
       ^^^^^^^^^^^^^^      ^^^^^^^^^^^^^^
       это адрес хоста     это broadcast (brd)
```

**Что делать:**

1. На Debian посмотрите реальный адрес:
   ```bash
   hostname -I
   # или
   ip -br addr
   ```
   Нужен адрес, который идёт после `inet`, например `192.168.203.10`.

2. В PuTTY введите этот адрес и подключайтесь.

3. Проверьте с Windows: `ping 192.168.203.10` — должен отвечать.

**Если с правильным адресом всё равно не заходит:**

- Убедитесь, что сам Windows-ПК находится в той же подсети `192.168.203.x` (`ipconfig` в cmd). Если ПК в другой сети (например, 192.168.1.x), а роутера между ними нет — они друг друга не увидят.
- На Debian проверьте, что sshd слушает порт 22:
  ```bash
  sudo systemctl status ssh
  ss -tln | grep :22
  ```
- Проверьте фаервол: `sudo ufw status` / `sudo iptables -L -n`.
- Если Debian — виртуальная машина (VirtualBox/VMware): для прямого доступа с хоста сетевой адаптер должен быть в режиме **Bridge** или **Host-only**; при NAT нужен проброс порта 22.

Начните с замены адреса — в 99% случаев при такой ошибке проблема именно в `.255`.

### USER
под ssh не пускает под root access denid

### ASSISTANT
Это стандартное поведение Debian: по умолчанию в `/etc/ssh/sshd_config` стоит

```
PermitRootLogin prohibit-password
```

то есть root может заходить **только по ключу**, а пароль для root по SSH отключён — отсюда и «Permission denied / Access denied», даже если пароль правильный.

**Как исправить (нужен доступ к консоли Debian или обычный пользователь по SSH):**

1. Убедитесь, что у root вообще задан пароль (при установке с sudo-пользователем он часто не задан):
   ```bash
   sudo passwd root
   ```

2. Откройте конфиг:
   ```bash
   sudo nano /etc/ssh/sshd_config
   ```
   Найдите строку `#PermitRootLogin prohibit-password` и замените на:
   ```
   PermitRootLogin yes
   ```
   Заодно проверьте, что есть:
   ```
   PasswordAuthentication yes
   ```

3. Перезапустите ssh:
   ```bash
   sudo systemctl restart ssh
   ```

После этого root с паролем должен пускать.

**Более правильный вариант (рекомендуется):**
- заходите по SSH под обычным пользователем и повышаете права через `su -` или `sudo`;
- либо оставьте `PermitRootLogin prohibit-password` и положите публичный ключ в `/root/.ssh/authorized_keys` — тогда root сможет входить по ключу без пароля.

Проверить текущее состояние можно командой:
```bash
sudo sshd -T | grep -i permitroot
```

Если после правки всё равно не пускает — посмотрите вывод `ssh -v root@192.168.203.x` со стороны Windows и последние строки `sudo journalctl -u ssh -n 20` на Debian, там будет видна причина отказа.

### USER
permitrootlogin without-password

### ASSISTANT
Вот и причина. `without-password` (в новых версиях то же самое называется `prohibit-password`) означает: **root по паролю не пускает, только по ключу**. Поэтому при вводе пароля и получаете Access denied.

Дальше два пути.

**Вариант 1 — разрешить вход по паролю (проще):**

```bash
sudo nano /etc/ssh/sshd_config
```
замените
```
PermitRootLogin without-password
```
на
```
PermitRootLogin yes
```
затем:
```bash
sudo passwd root          # задать пароль root, если его нет
sudo systemctl restart ssh
```

Проверить, что применилось: `sudo sshd -T | grep -i permitroot` → должно показать `permitrootlogin yes`. Если там всё ещё without-password — значит в конфиге строка встречается дважды (первая имеет приоритет), закомментируйте дубликат.

**Вариант 2 — оставить как есть и заходить по ключу (правильнее):**

1. На Windows в **PuTTYgen** сгенерируйте ключевую пару, сохраните приватный ключ, а публичный (строка `ssh-rsa AAAA...`) скопируйте.
2. На Debian (с консоли или из-под обычного пользователя):
   ```bash
   sudo mkdir -p /root/.ssh && sudo chmod 700 /root/.ssh
   echo "ssh-rsa AAAA...ваш_ключ..." | sudo tee /root/.ssh/authorized_keys
   sudo chmod 600 /root/.ssh/authorized_keys
   ```
3. В PuTTY: **Connection → SSH → Auth → Credentials** → укажите файл приватного ключа → подключайтесь под root без пароля.

Для домашней лаборатории проще вариант 1, но для сервера, смотрящего в интернет, лучше держать root только по ключу.

### ASSISTANT
Ок, настроим статику. Сначала посмотрим текущие параметры, чтобы подставить правильные (имя интерфейса, шлюз):

```bash
ip -br addr          # имя интерфейса и текущий IP
ip route             # строка default via ... — это ваш шлюз
```

Дальше зависит от того, чем настроена сеть.

**Вариант А — классический `/etc/network/interfaces`** (обычно на серверной Debian):

```bash
sudo nano /etc/network/interfaces
```

Найдите блок вида:
```
allow-hotplug eth0
iface eth0 inet dhcp
```
и замените на (имя интерфейса и шлюз — свои):
```
auto eth0
iface eth0 inet static
    address 192.168.203.20/24
    gateway 192.168.203.1
    dns-nameservers 192.168.203.1 8.8.8.8
```

Применить:
```bash
sudo systemctl restart networking
```
⚠️ Текущая SSH-сессия при этом отвалится — переподключайтесь уже на новый адрес.

**Вариант Б — NetworkManager** (если Debian с графической оболочкой):

Проще всего через `sudo nmtui`:
1. «Edit a connection» → выбираете ваше проводное подключение → Enter.
2. IPv4 CONFIGURATION: `<Automatic>` меняете на `<Manual>`.
3. «Addresses» → Add → `192.168.203.20/24`, Gateway: `192.168.203.1`, DNS: `192.168.203.1` (или `8.8.8.8`).
4. OK → затем `sudo nmcli con up <имя_соединения>` (сессия тоже отвалится).

**Пара советов:**
- Выберите адрес **вне диапазона DHCP** роутера (посмотрите в настройках роутера, например если пул .100–.199, берите .20), иначе роутер может выдать этот же адрес другому устройству — будут конфликты и «плавующие» проблемы.
- Не берите `.0` и `.255` — это адрес сети и broadcast.
- Маска `/24` подходит, если у вас обычная домашняя сеть 255.255.255.0.

После применения проверьте с Windows: `ping 192.168.203.20` и подключение PuTTY на новый адрес.

Вижу: интерфейс `eno1`, сейчас на DHCP. Замените блок основного интерфейса на статику.

Сначала (в соседней консоли) посмотрите текущие параметры, чтобы подставить правильные:

```bash
ip -br addr     # текущий IP на eno1
ip route        # default via 192.168.203.X — это шлюз
```

Теперь в редакторе замените:

```
# The primary network interface
allow-hotplug eno1
iface eno1 inet dhcp
```

на:

```
# The primary network interface
auto eno1
iface eno1 inet static
    address 192.168.203.20/24
    gateway 192.168.203.1
    dns-nameservers 192.168.203.1 8.8.8.8
```

(значения — свои: address — выбранный статический IP из той же подсети, gateway — то, что показал `ip route`; строку `iface eno1 inet6 auto` можно оставить или удалить, если IPv6 не нужен)

Сохраните (в mcedit — **F2**, выход **F10**) и примените:

```bash
systemctl restart networking
```

или

```bash
ifdown eno1 && ifup eno1
```

Проверка:

```bash
ip -br addr
ping -c 3 192.168.203.1     # пинг шлюза
ping -c 3 ya.ru             # работает ли DNS
```

Нюансы:
- Если вы сейчас сидите через SSH — после рестарта сессия отвалится, заходите на новый адрес. Судя по скриншоту, у вас консоль, так что не страшно.
- Статический адрес берите вне пула DHCP роутера, чтобы не пересечься с другим устройством.
- Если после настройки пропадёт DNS (пакет resolvconf стоит не всегда), просто пропишите вручную в `/etc/resolv.conf`:
  ```
  nameserver 192.168.203.1
  nameserver 8.8.8.8
  ```

После этого с Windows подключайтесь PuTTY на новый статический адрес.
