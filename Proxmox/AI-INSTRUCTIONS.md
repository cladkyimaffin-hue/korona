# Файл `AI-INSTRUCTIONS.md`

```markdown
# AI-INSTRUCTIONS.md

## Статус документа

Этот файл содержит обязательные инструкции для искусственного интеллекта,
работающего с репозиторием инфраструктурной документации.

Инструкции распространяются на:

- ответы по документации;
- диагностику Proxmox;
- работу с виртуальными машинами;
- работу с Ceph;
- работу с Windows Server;
- работу с шаблонами и клонами;
- работу с сетями;
- работу с резервными копиями;
- создание и изменение Markdown-файлов;
- обновление индексов;
- подготовку команд для администратора.

ИИ должен считать эти правила обязательными.

---

# 1. Приоритет правил

Использовать следующие уровни приоритета:

1. явно сформулированное требование пользователя;
2. текущая конфигурация и свежий вывод команд;
3. профильная документация конкретной системы или ВМ;
4. `Proxmox/INDEX.md`;
5. `AI-README.md`;
6. остальные документы репозитория;
7. официальная документация Proxmox, Microsoft, Ceph или другого поставщика;
8. общие знания ИИ.

Если пользователь просит действие, нарушающее безопасность production,
ИИ должен предупредить о риске и предложить безопасную процедуру.

Если пользователь требует выполнить опасную операцию без проверки, ИИ не
должен молча соглашаться.

---

# 2. Главная задача

Главная задача ИИ — дать точный, короткий, проверяемый и безопасный ответ.

ИИ не должен:

- демонстрировать знания без практической пользы;
- повторять весь репозиторий;
- предлагать несколько десятков вариантов без необходимости;
- скрывать неизвестные параметры;
- выдавать предположение за факт;
- запускать опасную процедуру без подтверждения;
- менять несвязанные документы;
- удалять исторические данные без запроса;
- придумывать IP, пароли, VM ID или номера разделов.

---

# 3. Режимы работы

Перед ответом определить режим задачи.

## 3.1. Режим поиска ответа

Использовать, если пользователь спрашивает:

- где находится информация;
- как настроена ВМ;
- какой используется storage;
- какой размер диска;
- зависит ли клон от шаблона;
- какая команда уже применялась.

Порядок:

1. определить ключевые слова;
2. открыть `Proxmox/INDEX.md`;
3. выбрать профильный файл;
4. прочитать YAML-контекст;
5. проверить `Quick Answers`;
6. дать краткий ответ;
7. указать источник в репозитории.

## 3.2. Режим диагностики

Использовать, если пользователь сообщает об ошибке.

Порядок:

1. переформулировать проблему одним предложением;
2. определить систему и объект;
3. указать наиболее вероятную причину;
4. отделить подтверждённые факты от предположений;
5. предложить только безопасные команды проверки;
6. объяснить ожидаемый результат;
7. после получения вывода предложить изменение;
8. описать риск и откат.

## 3.3. Режим изменения конфигурации

Использовать, если нужно изменить ВМ, диск, сеть, кластер или storage.

Перед изменением:

1. проверить объект;
2. проверить текущую конфигурацию;
3. убедиться, что ВМ имеет правильный VM ID;
4. проверить резервную копию;
5. определить, можно ли выполнить операцию онлайн;
6. указать возможный простой;
7. указать команду;
8. указать проверку результата;
9. указать способ отката.

## 3.4. Режим создания документа

Использовать, если пользователь просит создать Markdown-файл.

Файл должен содержать:

- YAML-метаданные;
- краткое AI-summary;
- key_takeaways;
- dont_repeat;
- assumptions;
- commands;
- config_snippets;
- related_files;
- теги;
- контрольный список;
- быстрые ответы;
- типовые ошибки;
- порядок проверки;
- откат или предупреждение о невозможности отката.

После создания нового файла нужно предложить обновить индекс.

## 3.5. Режим обновления индекса

Использовать, если создан новый файл или изменилось назначение
существующего файла.

В индекс добавить:

- название файла;
- относительную ссылку;
- краткое описание;
- вопросы, на которые отвечает файл;
- место в дереве решений;
- теги или категорию.

Не удалять существующие записи без проверки ссылок.
