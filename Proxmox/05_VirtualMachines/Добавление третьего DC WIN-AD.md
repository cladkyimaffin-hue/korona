# Добавление третьего контроллера домена (WIN-AD → AD) — успешно

## Обновление от администратора (2026-09-11)
ВМ 2002 впоследствии переименована: `WIN-AD` → **`AD`** (в Proxmox
отображается как `2002 (AD)`) — согласуется с финальными командами этой
же сессии, где сервер уже фигурирует под именем `AD`.

## Цель и параметры целевой ВМ
Повысить ВМ 2002 (`win-ad-ds-01`, узел pve01, клон шаблона 2000,
Windows Server 2022, `192.168.200.225/22`) до третьего писабельного
контроллера домена `krnn.ru`, рядом с `ANDQ` (192.168.200.10) и `DC`
(192.168.200.2, оба Windows Server 2025).

## Хронология: три попытки

### Попытка 1 — прервана случайно, ошибка 8200
`Install-ADDSDomainController` запущена, но во время длительного (5-15
минут) выполнения без вывода администратор случайно нажал `Ctrl+C`/`Ctrl+Z`
и подтвердил отмену. Служба `NTDS` не установилась. Повторный запуск без
очистки дал:
```
EVENTLOG (Error): NTDS Database / Архивация данных : 2542
Сервер службы каталогов обнаружил, что база данных была заменена.
```
Код **8200** — рассинхронизация `DSA Database Epoch` в реестре с
файлом `ntds.dit` от прерванной попытки.

**Очистка перед повтором:**
```powershell
Test-Path C:\Windows\NTDS\ntds.dit                                                          # → False
Get-ChildItem C:\Windows\NTDS -Force -ErrorAction SilentlyContinue                            # → пусто
Get-ItemProperty 'HKLM:\System\CurrentControlSet\Services\NTDS\Parameters' -Name 'DSA Database Epoch' -ErrorAction SilentlyContinue  # → пусто
```
Артефактов не найдено, но выполнена `Restart-Computer -Force` для верности.

### Попытка 2 — зависла на ~24 часа, потребовала принудительной остановки процесса

Повторный чистый запуск `Install-ADDSDomainController` — окно PowerShell
перестало обновляться и оставалось в таком состоянии **сутки**.

**Первая гипотеза (QuickEdit Mode) — не подтвердилась.** Диагностика из
**второй, отдельной сессии** (не трогая зависшее окно) через
`Get-Process powershell` показала процесс, реально нагружающий CPU —
то есть не консоль встала на паузу, а сам процесс DCPromo не завершался.

**Решение — принудительная остановка:**
```powershell
Stop-Process -Id 4216 -Force
Get-Process powershell
```
После остановки — файлы `C:\Windows\NTDS\*` (`ntds.dit`, `edb.log` и др.)
**остались заблокированы** движком ESE (`Stop-Process -Force` не даёт
процессу штатно закрыть файловые дескрипторы) — для снятия блокировки
потребовалась перезагрузка сервера.

**Очистка осиротевшего объекта в AD:** объект `CN=WIN-AD,CN=Servers,...`
не откатился автоматически. Проверено — дочернего объекта `NTDS Settings`
у него нет (`Get-ADObject` → «Объект каталога не найден»), значит, ANDQ и
DC никогда не регистрировали `WIN-AD` как полноценного партнёра —
удаление простым `Remove-ADObject`, **без** `ntdsutil metadata cleanup`
(та процедура нужна только при наличии `NTDS Settings`).

Далее — установка накопительных обновлений Windows (устаревший билд
20348 без патчей упоминался как возможный сопутствующий фактор ошибки
1749), перезагрузка, повторная проверка чистоты состояния. Второй похожий
инцидент (ещё один зависший процесс, PID 6548) обработан тем же способом.

### Попытка 3 — успешна, подтверждено инструментально

```powershell
Install-ADDSDomainController `
  -DomainName "krnn.ru" `
  -Credential (Get-Credential) `
  -SiteName "Default-First-Site-Name" `
  -InstallDns:$true `
  -NoGlobalCatalog:$false `
  -ReplicationSourceDC "ANDQ.krnn.ru" `
  -DatabasePath "C:\Windows\NTDS" `
  -LogPath "C:\Windows\NTDS" `
  -SysvolPath "C:\Windows\SYSVOL" `
  -SafeModeAdministratorPassword (Read-Host -AsSecureString "Введите пароль DSRM") `
  -Confirm:$false
```

**Подтверждение успеха (реальный вывод из этой сессии):**
```
repadmin /replsummary
 AD     :16s    0 сбоев / 10
 ANDQ   09m:08s 0 сбоев / 10
 DC     07m:49s 0 сбоев / 10

repadmin /showrepl → все входящие соседи "Последняя попытка ... успешна"
Get-ADDomainController -Filter * → 3 DC: DC, ANDQ, AD
dcdiag /v /c → Connectivity, MachineAccount, NCSecDesc, ObjectsReplicated,
               Replications, RidManager, Services, Topology,
               VerifyReferences, DNS (Auth/Basc/Forw/Del/Dyn/RReg) — все PASS
```

**Единственное, что оставалось на момент документа — SYSVOL (DFSR), не сама AD:**
```
dcdiag /test:Advertising → не пройдена (сервер ещё не "объявляет" себя — ждёт SYSVOL)
dcdiag /test:NetLogons   → не пройдена (\\AD\netlogon недоступен по той же причине)
Get-WmiObject ... DfsrReplicatedFolderInfo → State: 2 (Initializing, не 4/Normal)
```
Это ожидаемое временное состояние: DFSR-репликация SYSVOL идёт отдельно
от репликации базы AD. Ускорено через:
```powershell
Install-WindowsFeature RSAT-DFS-Mgmt-Con
dfsrdiag pollad
dfsrdiag backlog /rgname:"Domain System Volume" /rfname:"SYSVOL Share" /smem:DC /rmem:AD
```
Бэклог показал конечное и уменьшающееся число (99 файлов — типовой объём
стандартных GPO), что подтвердило: соединение DFSR установлено и активно
реплицирует, а не зависло.

## Проверка результата
- [x] `Get-ADDomainController -Filter *` — 3 контроллера домена: `DC`, `ANDQ`, `AD`.
- [x] `repadmin /replsummary`/`repadmin /showrepl` — репликация со всеми партнёрами без ошибок.
- [x] `dcdiag /v /c` — все ключевые тесты PASS (кроме Advertising/NetLogons, см. ниже).
- [ ] `dcdiag /test:Advertising`, `dcdiag /test:NetLogons`, `Get-SmbShare` (SYSVOL/NETLOGON) — на момент последнего сообщения в этой сессии ещё не проходили: SYSVOL (DFSR) был в состоянии `Initializing` (State=2), бэклог 99 файлов активно уменьшался. **Финальное подтверждение State=4/событие 4114 в архиве не найдено** — при следующем обращении к этой ВМ проверить, что синхронизация действительно завершилась.
- [ ] Осиротевший объект `WIN-AD` (если остались следы старого имени после переименования в `AD`) — сверить отдельно.
- [ ] Замечена, но не разобрана мелкая аномалия: `Get-ADDomainController -Filter *` в какой-то момент показал `ANDQ` с IP `172.27.48.1` вместо ожидаемого `192.168.200.10` — вероятно, локальная особенность разрешения имени на сервере `AD`, не блокирует работу, но не проверена отдельно.
- [ ] Обратные DNS-зоны для подсети — упоминались как оставшаяся задача, не подтверждены выполненными.
