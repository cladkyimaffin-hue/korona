# План миграции ВМ для изоляции 1С ERP

> ⛔ **ПЛАН ОТМЕНЁН решением администратора (2026-10-28).** Миграция не выполнялась и не планируется; документ сохранён как историческая запись. Основание отмены не зафиксировано (вопрос о переносе ВМ ранее был закрыт администратором 2026-10-15 без основания). Шаги раздела 3 не выполнять, идею изоляции 1С на `pve01` действующей не считать.

## 1. Контекст и цель
- **Окружение:** Proxmox VE 9.2.11, 2 узла: `pve01`, `pve02`. Ceph-кластер (4 OSD).
- **Проблема:** пользователи жалуются на медленную работу 1С ERP. **VERIFIED:** все ВМ размещены на `pve01` (по словам администратора), он загружен на ~200 GiB RAM из 250 GiB; `pve02` практически свободен (~14 GiB RAM, это Ceph и система).
- **INFERRED:** причина жалоб — эффект «шумного соседа» (конкуренция ВМ за CPU и RAM на `pve01`). Не подтверждено: замеров нагрузки CPU хоста, NUMA и переподписки vCPU, а также замеров во время жалоб, нет.
- **UNKNOWN (альтернативные гипотезы, не проверены):** настройки SQL Server (`MAXDOP`, ожидания `CXPACKET`), задержка записи файла данных базы, скорость `public_network` Ceph, клиентская сторона (терминальный сервер, антивирус).
- **VERIFIED (расследование 2026-09-17):** ВМ 2001 одна, сервер приложений 1С и SQL Server работают на ней вместе; `srv1c` — имя инстанса SQL, а не отдельная ВМ.
- **Идея администратора (не утверждена):** оставить на `pve01` только ВМ 1С ERP, остальные перенести на `pve02`.
- **Цель:** снять нагрузку с `pve01`, если проверки подтвердят пользу, не ухудшив работу остальных сервисов.
- Метки достоверности: VERIFIED — подтверждено выводом команд; INFERRED — вывод, напрямую не подтверждён; UNKNOWN — данных нет.

## 2. Текущее распределение ресурсов (2026-10-07)

| Узел | RAM Total | RAM Used | RAM Free | Роль |
|---|---|---|---|---|
| `pve01` | 250 GiB | ~200 GiB | ~50 GiB | Хостит все ВМ, включая 1С ERP. |
| `pve02` | 251 GiB | ~14 GiB | ~236 GiB | Практически свободен. |

Подписи узлов во вставке `free -h` были перепутаны; соответствие узлам установлено по словам администратора (все ВМ на `pve01`).

**Состояние Ceph (2026-10-07):** `osd_memory_target` = 4294967296 (4 ГБ, по умолчанию), **не менялся** (`ceph config get osd.0 osd_memory_target`); для `osd.2` не проверялось. Увеличение до 8 ГБ для NVMe-демонов — **INFERRED**: `ceph osd perf` на простое показал 0 мс, замеров под нагрузкой нет.

## 3. Стратегия миграции

0. **Подтвердить причину измерениями** (раздел 4). Если замеры не покажут конкуренцию за ресурсы `pve01`, миграция не решит проблему.
1. **Идентификация компонентов 1С:** ВМ 2001 (сервер 1С и SQL на одной ВМ) остаётся на `pve01`.
2. **Инвентаризация остальных ВМ:** получить список запущенных ВМ через `qm list` на `pve01`. В кластере известны ВМ 2002 (`AD`, контроллер домена), ВМ 2003 (`TC.KRNN.RU`, терминальный сервер RDS); остальные — по `qm list`.
3. **Проверка совместимости:** на `pve02` достаточно RAM, CPU и места на Ceph; нет ВМ с локальным хранилищем.
4. **Пошаговая миграция:** по одной ВМ (или логическими группами) в нерабочее время, начиная с наименее критичной, через `qm migrate <vmid> pve02`. Для ВМ на общем хранилище Ceph переносится только состояние памяти.
5. **Верификация:** после каждой ВМ проверить доступность и отсутствие ошибок в логах Proxmox.

## 4. Проверки до миграции (только чтение)
- `qm list`; для каждой ВМ `qm config <vmid>` (vCPU, RAM, диски).
- Процессор и NUMA на `pve01`: `lscpu`, `numactl -H`; сумма vCPU всех запущенных ВМ и число потоков хоста.
- `ha-manager status`: есть ли ресурсы HA, которых затронет перенос.
- Скорость и загрузка канала под `vmbr0` (`public_network` Ceph): `ip -br link`, `ethtool <интерфейс> | grep -i speed`. ВМ на `pve02` обращаются к OSD на `pve01` по этой сети.
- Сеть для миграции (по умолчанию используется сеть управления) и нагрузка на неё.
- **Замеры во время жалобы:** на `pve01` — загрузка CPU (`top`, `mpstat`), `ceph -s` (slow ops), `ceph osd perf` несколько раз подряд; в ВМ 2001 — очереди дисков и CPU, активные запросы SQL.
- Затронутые сервисы: контроллеры домена, RDS, WMS; согласовать окно и откат.

## 5. Чек-лист выполнения
- [ ] Выполнить `free -h` на обоих узлах (с явной подписью узла).
- [ ] Выполнить `qm list` на `pve01`.
- [ ] Провести проверки из раздела 4, в том числе замеры во время жалобы.
- [ ] Принять решение о миграции по результатам замеров.
- [ ] Выполнить `ceph df` для проверки свободного места в пулах `ceph-fast` и `ceph-bulk`.
- [ ] Составить окончательный список ВМ для миграции на `pve02`.
- [ ] Выполнить миграцию первой ВМ (наименее критичной).
- [ ] Проверить доступность мигрированной ВМ.
- [ ] Продолжить миграцию остальных ВМ по списку.

## 6. ⛔ Don't repeat
- Не мигрировать ВМ 1С ERP на `pve02` без явного запроса администратора.
- Не выполнять `qm migrate` при недостатке свободного места на Ceph-пуле назначения.
- Не мигрировать ВМ с привязкой к локальному хранилищу (local/local-lvm) без предварительного переноса дисков на Ceph.
- Не считать причину жалоб установленной без замеров во время жалоб.
