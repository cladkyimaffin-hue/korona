# Проброс USB-ключа HASP в ВМ 2001 (Srv1c)

## Симптомы
После добавления USB-устройства через GUI Proxmox (`VM → Hardware → Add →
USB Device`) и перезагрузки ВМ 2001 — ключ защиты 1С внутри Windows не
появился.

## Диагностика

**Проверить, что реально проброшено, в конфиге ВМ:**
```bash
qm config 2001 | grep usb
```
Показало: `usb0: host=12d1:0003`.

**Посмотреть полный список USB-устройств на хосте:**
```bash
lsusb
```
```
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
Bus 001 Device 002: ID 12d1:0003 Huawei Technologies Co., Ltd. Keyboard/Mouse KVM 1.1.0
Bus 001 Device 003: ID 0529:0001 Aladdin Knowledge Systems HASP copy protection dongle
Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub
```

## Корневая причина
`12d1:0003` — это **встроенный KVM/IPMI USB-контроллер клавиатуры/мыши
сервера Huawei 2288H V5**, присутствующий в системе всегда, а не
подключённый пользователем ключ. При выборе устройства через GUI он был
выбран по ошибке вместо реального ключа `0529:0001` (Aladdin/HASP).

## Решение
```bash
qm set 2001 --usb0 host=0529:0001
```
**Проверка:**
```bash
qm config 2001 | grep usb
```
Ожидаемо: `usb0: host=0529:0001`.

Если ВМ уже работает — для применения изменения требуется её перезагрузка
(не hotplug автоматически); если выключена — при следующем запуске ключ
должен определиться внутри Windows сразу.

## ⛔ Don't repeat
См. `dont_repeat` во фронтматтере — главное: `12d1:0003` на серверах
Huawei 2288H V5 это служебный KVM-контроллер, не пользовательский ключ.

## Проверка результата — подтверждено
- [x] `qm config 2001 | grep usb` → `usb0: host=0529:0001`.
- [x] Замена выполнена командой без ошибок (`update VM 2001: -usb0 host=0529:0001`).
- [ ] Появление ключа в Диспетчере устройств Windows и работа лицензирования 1С — подтверждение результата внутри гостевой ОС в исходной переписке не зафиксировано, проверить при следующем обращении к этой ВМ.

## Откат
```bash
qm set 2001 --usb0 host=12d1:0003
```
