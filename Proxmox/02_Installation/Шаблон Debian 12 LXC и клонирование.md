# Создание шаблона Debian 12 LXC в Proxmox VE и развёртывание клонов

## Что настраивается и зачем
Многоразовый шаблон Debian 12 LXC для быстрого развёртывания новых
контейнеров без повторной ручной установки и настройки с нуля.

## Предварительные условия
- [ ] Шаблон Debian 12 загружен: `ls /var/lib/vz/template/cache/` → `debian-12-standard_12.12-1_amd64.tar.zst`.

## Шаги: создание контейнера-заготовки

**1. Создать контейнер (корневой диск — только через `--rootfs`, не `--disk`):**
```bash
pct create 200 local:vztmpl/debian-12-standard_12.12-1_amd64.tar.zst \
  --rootfs ceph-fast:100 \
  --memory 4096 --cores 2 \
  --net0 name=eth0,bridge=vmbr0 \
  --hostname zabbix-lxc --unprivileged 1
```
`--disk` для LXC не поддерживается (`Unknown option: disk`) — только `--rootfs`.

**2. Настроить автозапуск сети внутри контейнера.** По умолчанию
`/etc/network/interfaces` в шаблонном образе содержит только `lo`, `eth0`
не поднимается автоматически после перезагрузки:
```bash
pct exec 200 -- bash -c "echo -e '\nauto eth0\niface eth0 inet dhcp' >> /etc/network/interfaces"
pct reboot 200
pct exec 200 -- ip -4 addr show eth0    # проверка после перезагрузки
```

**3. При необходимости — временный статический IP** (для проверки перед шаблонированием):
```bash
pct set 200 --net0 name=eth0,bridge=vmbr0,ip=<IP>/22,gw=<gateway>
```

## Шаги: подготовка и создание шаблона

**4. Остановить контейнер перед шаблонированием:**
```bash
pct shutdown 200
```

**5. Убрать статический IP/gateway из net0** — иначе все клоны получат один и тот же адрес:
```bash
pct set 200 --net0 name=eth0,bridge=vmbr0
pct config 200 | grep net0    # убедиться, что ip=/gw= больше нет
```

**6. Преобразовать в шаблон:**
```bash
pct template 200
```
⚠️ Необратимо в рамках этого ID — контейнер после этого предназначен только для клонирования.

## Шаги: клонирование из шаблона

**7. Клонировать (сеть — НЕ через `--net0` в `pct clone`, он такой параметр не принимает):**
```bash
pct clone 200 <новый_id> --hostname <новое_имя>
```

**8. Настроить сеть клона отдельной командой, уже после клонирования:**
```bash
pct set <новый_id> --net0 name=eth0,bridge=vmbr0,ip=<IP>/22,gw=<gateway>
pct start <новый_id>
```

## Изменение ID существующего контейнера/шаблона
В Proxmox VE нет прямой команды переименования VMID. Единственный
поддерживаемый способ (актуально и для дисков на Ceph RBD):
```bash
vzdump <старый_id> --mode snapshot --storage local
# затем restore резервной копии с новым ID через GUI или qmrestore/pct restore
```
Более лёгкая альтернатива, если нужно только имя — сменить `hostname`/`description`, не трогая ID:
```bash
pct set 200 --hostname debian12-pattern --description "Debian12 pattern"
```

## Типовые донастройки сразу после клонирования

**SSH «доступ запрещён» на свежем клоне.** Debian по умолчанию не пускает
root по паролю (`PermitRootLogin prohibit-password`). Не имея SSH, зайти
можно прямо с ноды:
```bash
pct start <id>
pct enter <id>
sed -i 's/#PermitRootLogin prohibit-password/PermitRootLogin yes/' /etc/ssh/sshd_config && systemctl restart ssh
```

**`apt-get`/`apt` возвращает 404 Not Found на пакетах.** Кэш списков
пакетов в образе шаблона устарел (собран раньше, чем актуальные зеркала).
Решение — простое обновление индексов:
```bash
apt-get update
```

**Midnight Commander (`mc`) показывает «крякозябры» вместо рамок.**
Причина — локаль `C` (не UTF-8) в свежем контейнере (`locale` → `LANG=C`).
Установить и сгенерировать локаль UTF-8, затем перезайти в сессию.

**Отдельный случай: SSH зависает на новом клоне (не связан с pam_systemd/logind).**
Если зависание — это классический тайм-аут обратного DNS-резолвинга
(другая причина, чем в `LINUX-SSH-PAM-SYSTEMD-ZABBIX-2026-001` — там
виноват был `pam_systemd.so`/`systemd-logind`), можно обойти интерактивный
логин и вписать параметр напрямую с хоста:
```bash
pct exec <id> -- bash -c "echo 'UseDNS no' >> /etc/ssh/sshd_config && systemctl restart ssh"
```

## ⛔ Don't repeat
- `--disk` не работает для LXC — только `--rootfs`.
- `--net0` не работает в `pct clone` — задавать сеть отдельной командой `pct set` после клонирования.
- Не шаблонировать контейнер с сохранённым статическим IP.
- Не считать успешный `pct clone` подтверждением рабочей сети клона без отдельной проверки.
- Нет команды смены VMID напрямую — только через backup/restore.

## Проверка результата
- [ ] `pct config <id> | grep net0` — сеть клона настроена индивидуально, IP не совпадает с другими клонами.
- [ ] `pct exec <id> -- ip -4 addr show eth0` — адрес присутствует после перезагрузки без ручного вмешательства.
- [ ] SSH-вход на клон проходит без зависаний и без «доступ запрещён».

## Зафиксированные в этой сессии контейнеры (для истории, не как рецепт)
| ID | Роль | Итог |
|---|---|---|
| 200 → далее переименован (hostname `debian12-pattern`) | Исходный шаблон | Templated, IP убран |
| 500 | Клон, hostname `zabbix` | Финальный статический IP `192.168.200.233/22` (задан вручную администратором, отличается от изначально запланированного `192.168.203.93`) |
| 700 | Клон из шаблона (после переименования шаблона) | SSH зависал из-за обратного DNS, исправлено `UseDNS no` |
