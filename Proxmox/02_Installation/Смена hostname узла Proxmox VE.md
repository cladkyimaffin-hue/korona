# Смена hostname узла Proxmox VE до вступления в кластер

## Что настраивается и зачем
Корректная смена имени узла (hostname/FQDN) Proxmox VE после установки, без
рассинхронизации служб и ошибок SSL-сертификата. Процедура применима, когда
узел **ещё не в кластере** (проверяется командой `pvecm status`) — для узла
уже в составе кластера порядок другой и здесь не описан (см. раздел
«Не покрыто в этой версии» ниже).

## Предварительные условия
- [ ] Узел не входит в активный кластер, либо кластер временно остановлен для обслуживания.
- [ ] Процедура выполняется в maintenance-окне — перезагрузка остановит работающие ВМ.

## Шаги

1. **Поправить `/etc/hosts`.** Заменить строку с IP узла — сначала FQDN, затем короткое имя. Имя узла не должно указывать на `127.0.0.1`:
   ```
   127.0.0.1 localhost.localdomain localhost
   192.168.202.121 pve01.krnn.ru pve01
   ```

2. **Поменять `/etc/hostname`** (через Node → Shell или по SSH):
   ```bash
   echo "pve01" > /etc/hostname
   ```

3. **Перезагрузить узел:**
   ```bash
   reboot
   ```

4. **После перезагрузки** список ВМ в веб-интерфейсе будет пуст — конфигурации лежат в каталоге со старым именем. Перенести их:
   ```bash
   ls /etc/pve/nodes/
   # если каталог pve01 ещё не создан:
   mv /etc/pve/nodes/pve /etc/pve/nodes/pve01

   # если pve01 уже создан (пустой) — слить содержимое:
   cp -a /etc/pve/nodes/pve/. /etc/pve/nodes/pve01/
   rm -rf /etc/pve/nodes/pve
   ```
   Затем перезапустить службы (или ещё раз `reboot`):
   ```bash
   systemctl restart pvedaemon pveproxy pvestatd pvescheduler
   ```

## Проверка результата
- [ ] ВМ, LXC и снапшоты отображаются на узле с новым именем (`pve01`).
- [ ] Самоподписанный SSL-сертификат останется со старым именем — не критично; при необходимости перегенерировать в Node → Certificates.

## ⛔ Don't repeat
- Не менять hostname только через `/etc/hostname`/`hostnamectl` без обновления `/etc/hosts` — рассинхронизация и ошибки SSL.
- Не выполнять на узле, уже входящем в кластер, без предварительного вывода из кластера.

## Не покрыто в этой версии документа

дополнительно требуется правка `corosync.conf` при остановленном кластере.
