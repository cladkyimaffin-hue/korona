Шаг 2.2 — Ответ о лицензиях RDS CAL и фиксация ресурсов

**Объяснение / действие:**
1. **Где взять RDS CAL:** Клиентские лицензии доступа (RDS CAL) являются платными. Они приобретаются у официальных реселлеров Microsoft (партнёров) или через программы корпоративного лицензирования (Volume Licensing, CSP). Они **не входят** в стандартную лицензию Windows Server.
2. **Тип лицензий:** Для 10 человек обычно выбирают **User CAL** (лицензия на пользователя, позволяет одному человеку подключаться с любого числа устройств) или **Device CAL** (лицензия на устройство, выгодно, если несколько человек работают посменно за одним и тем же терминалом).
3. **Технический нюанс:** После установки роли узла сеансов (Session Host) Microsoft предоставляет **120-дневный льготный период**. В это время сервер будет полноценно работать без настроенного сервера лицензий. Это даёт время на легальную покупку и последующую активацию лицензий на контроллере домена.
4. **Ресурсы:** 4 vCPU и ~48 ГБ RAM — это более чем достаточно для 10 пользователей (ориентировочное потребление: 2 ГБ на ОС + 3–4 ГБ на 10 сессий = ~5–6 ГБ суммарно).

Шаг 3.2 — Создание базового развертывания RDS (Remote Desktop Services Deployment)

**Объяснение / действие:**
После установки роли Session Host необходимо создать базовое развертывание RDS. Это инициализирует службу Remote Desktop Services и создаст необходимые конфигурации.

Откройте PowerShell от имени администратора на ВМ 2003 и выполните:

```powershell
New-RDSessionDeployment -ConnectionBroker $env:COMPUTERNAME -SessionHost $env:COMPUTERNAME
```

**Пояснение:**
- `$env:COMPUTERNAME` — автоматически подставит текущее имя сервера (не нужно угадывать hostname)
- `-ConnectionBroker` — роль брокера подключений (управляет сессиями пользователей)
- `-SessionHost` — роль узла сеансов (уже установлена на этом сервере)

Команда создаст базовую конфигурацию RDS, где ВМ 2003 будет выполнять обе роли.

**Как проверить результат:**
1. Дождитесь завершения команды (вывод покажет прогресс и завершение).
2. Выполните проверку:
```powershell
Get-RDServer
```
Ожидаемый вывод: таблица с двумя записями для вашего сервера — одна с `Roles: RDS-CONNECTION-BROKER`, другая с `Roles: RDS-SESSION-HOST`.

**Риск:** ⚠️ Команда изменяет конфигурацию служб RDS. Если что-то пойдёт не так, потребуется переустановка ролей.

**Откат:** Если команда завершится с ошибкой, можно удалить deployment командой:
```powershell
Remove-RDServer -Server $env:COMPUTERNAME -Role "RDS-CONNECTION-BROKER" -Force

```
