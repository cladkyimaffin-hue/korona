# AI-environment facts — Proxmox

Этот файл содержит факты инфраструктуры, которые ИИ должен использовать как
контекст. Источником истины для конкретной операции остаются текущий вывод

как текущее состояние.

## Proxmox

- Версия: **Proxmox VE 9.2.11** (Debian 13 "trixie", ядро 7.0.14-15-pve).
- Кластер: **`krnn`**.
- Узлы: **`pve01` — `192.168.202.121/22`**, **`pve02` — `192.168.202.179/22`**.
- QDevice: **`qdevice.krnn.ru` — `192.168.200.84`**, Debian 13 (заменён 2026-09-30; прежний хост `192.168.202.251` выведен из эксплуатации).
- Кластер состоит из двух полноценных Proxmox-узлов плюс внешний Corosync QDevice; QDevice не является Ceph-узлом.
- Управляющая сеть: `192.168.200.0/22`, bridge `vmbr0`, gateway `192.168.200.1`.

## Сеть Ceph

- **Кластерная сеть Ceph (`cluster_network`)**: `10.10.11.0/24`.
- **Интерфейс**: `nic0` (прямое оптическое соединение point-to-point 10 GbE между pve01 и pve02, без коммутатора).
- **IP-адреса**: `pve01`: `10.10.11.1/24`, `pve02`: `10.10.11.2/24`.
- **MTU**: Строго **9000** (Jumbo Frames) на интерфейсе `nic0` на обоих узлах. Критично для производительности и стабильности Ceph. Значение сохранено в `/etc/network/interfaces` (строка `mtu 9000` в блоке `iface nic0 inet static` на обоих узлах, 2026-10-01); синтаксис проверен и применён в runtime через `ifreload -a` без ошибок (2026-10-07). Проверка перезагрузкой узла в плановое окно.
- **Публичная сеть Ceph (`public_network`)**: `192.168.200.0/22` (явно задана в `/etc/ceph/ceph.conf` и конфигурации мониторов).
- **Физический линк `public_network`**: `nic2` (Lom3) на обоих узлах, `1000 Mb/s` (VERIFIED 2026-10-15). Значение `ethtool vmbr0` 10000 Mb/s на pve01 — скорость моста, не линка. Физическая схема — `PROXMOX-NETWORK-TOPOLOGY-2026-001`.
- **Статус `bond0` (`nic4`/`nic5`, `10.10.10.0/24`)**: не используется для трафика Ceph. VERIFIED 2026-10-15: `nic4` и `nic5` на обоих узлах без линка, `bond0` DOWN. На схеме администратора `bond0` подписан как «SFP+ Cluster Network» — расхождение в `00_Meta/CONFLICTS.md` (OPEN). Любые упоминания его использования для Ceph являются устаревшими.

## Ceph

- Ceph: **Squid 19.2**.
- На каждом узле по два OSD: NVMe для `ceph-fast` и SSD `sdb` для `ceph-bulk`.
- В подтверждённой схеме всего четыре OSD.
- `ceph-fast`: NVMe, `Size=2`, `Min Size=1`.
- `ceph-bulk`: SSD, `Size=2`, `Min Size=1`.
- Мониторы Ceph: два — `mon.pve01` (`192.168.202.121`) и `mon.pve02` (`192.168.202.179`), `monmap` epoch 2; записей старой сети `10.10.10.x` нет (проверено 2026-10-01).
- CRUSH: правила `replicated_rule`, `nvme-replicated`, `ssd-replicated` используют `chooseleaf_firstn` с типом `host`; пулы `.mgr`, `ceph-fast`, `ceph-bulk` — `size 2`, `min_size 1` (проверено 2026-10-01).
- Системные диски не использовать для OSD.
- Перед операциями с OSD проверять `lsblk`, serial/model/WWN и отсутствие нужных данных.
- `osd_memory_target`: глобальное значение по умолчанию — 4 ГБ (`4294967296` байт). **Не менялось:** `ceph config get osd.0 osd_memory_target` на `pve01` вернул `4294967296` (2026-10-07), индивидуального переопределения для `osd.0` нет; команды `ceph config set … 8589934592` не выполнялись; для `osd.2` не проверялось. Увеличение до 8 ГБ для NVMe-демонов (`osd.0`, `osd.2`) — **INFERRED**: связь с жалобами на задержки не подтверждена замерами под нагрузкой (`ceph osd perf` на простое показал 0 мс), необходимость изменения не доказана.

## Важные ограничения

- Не считать QDevice третьей Ceph-нодой.
- Не путать историческую скорость Ceph-сети 1 GbE с текущей 10 GbE.
- Не использовать Linked Clone для production-ВМ без явного запроса.
- Не удалять Recovery-раздел Windows без `Get-Disk`/`Get-Partition`, резервной копии и подтверждения.
- Не выполнять destructive-команды Ceph (`wipefs`, `sgdisk`, создание OSD) без проверки диска.
- Перед операцией с VM/CT проверять текущие `qm config`, `qm status`, `pct config`, `pct list`.
- Исторические команды и имена файлов из старых миграций не считать актуальными путями: актуальный список находится в `00_Meta/registry.csv`.
- **Не использовать `bond0` (10.10.10.0/24) для трафика Ceph.** Активная и единственная кластерная сеть — `nic0` (10.10.11.0/24) с MTU 9000. Изменение этого параметра без явного запроса и аудита запрещено.
- При настройке или проверке сетей Ceph всегда сверять `/etc/ceph/ceph.conf` и вывод `ceph config dump`, так как локальный конфиг имеет приоритет при инициализации демонов OSD.
