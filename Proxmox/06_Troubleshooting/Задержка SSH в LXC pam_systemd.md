# Устранение задержки SSH-входа в LXC (zabbix) из-за pam_systemd.so

## 1. Симптомы
- SSH-аутентификация по паролю проходила без заметной задержки.
- После `Authentication succeeded` интерактивная сессия зависала примерно на 60 секунд, командная строка появлялась только после тайм-аута.
- Неинтерактивная команда (`ssh host "echo TEST && date"`) выполнялась быстро — задержка была именно на интерактивном входе.
- На соседнем узле `pve01` (не LXC, полноценная система) та же операция выполнялась мгновенно — асимметрия стала отправной точкой диагностики.

## 2. Отвергнутые гипотезы

| Гипотеза | Статус | Почему отклонена |
|---|---|---|
| Обратный DNS-резолвинг клиента (`UseDNS`) | ❌ Отклонена | На узле уже стоит `UseDNS no`; к тому же неинтерактивные команды выполняются быстро |
| GSSAPI/Kerberos-аутентификация | ❌ Отклонена | Пароль аутентифицируется быстро, пауза — уже после успешной аутентификации |
| Скрипт MOTD или shell-профиль (`.bashrc`/`.profile`) | ❌ Отклонена | MOTD содержит только `uname`, профили без долгих команд |
| **`pam_systemd.so` ждёт недоступный `systemd-logind`** | ✅ **Подтверждена** | См. диагностику ниже |

## 3. Диагностика

```bash
# 1. Параметры SSH-сервера — не UseDNS/GSSAPI
grep -E "^(UseDNS|GSSAPIAuthentication|GSSAPICleanupCredentials|UsePAM)" /etc/ssh/sshd_config

# 2. Verbose-подключение клиентом — где именно возникает пауза
ssh -v root@192.168.200.223
# → задержка после "Entering interactive session"

# 3. Контрольная неинтерактивная команда — базовый SSH и сеть работают
ssh -o StrictHostKeyChecking=no root@192.168.200.223 "echo NON_INTERACTIVE_TEST && date"

# 4. MOTD и shell-профили — не причина
ls -la /etc/update-motd.d/; tail -30 /root/.bashrc; cat /root/.profile

# 5. Статус systemd-logind — КЛЮЧЕВОЙ ШАГ
systemctl status systemd-logind --no-pager -l
# → failed, status=226/NAMESPACE

# 6. Журнал systemd-logind
journalctl -u systemd-logind --no-pager -n 20
# → "Failed to set up mount namespacing: /run/systemd/unit-root/proc: Permission denied"

# 7. PAM-конфигурация
cat /etc/pam.d/common-session
# → строка "session optional pam_systemd.so"
```

## 4. Корневая причина
`systemd-logind.service` не может запуститься внутри LXC-контейнера
(код выхода `226/NAMESPACE`, `Permission denied` при создании mount
namespace — стандартное ограничение непривилегированных LXC-контейнеров).
В `/etc/pam.d/common-session` был включён необязательный
(`session optional`) модуль `pam_systemd.so`, который при интерактивном
входе пытается взаимодействовать с недоступным `logind` и ждёт тайм-аута
~60 секунд, прежде чем сессия продолжится без него.

## 5. Решение
Закомментировать строку в `/etc/pam.d/common-session`:
```bash
sed -i 's/^\([[:space:]]*session[[:space:]]\+optional[[:space:]]\+pam_systemd\.so\)/# \1/' /etc/pam.d/common-session
```
Команда идемпотентна (не добавит повторный `#` при повторном запуске) и
меняет только строку, начинающуюся с `session optional pam_systemd.so`.

**До:**
```
session required pam_unix.so
session optional pam_systemd.so
```
**После:**
```
session required pam_unix.so
# session optional pam_systemd.so
```

## 6. ⛔ Don't repeat
- Не начинать с отключения `pam_systemd.so` без проверки `systemd-logind`/`journalctl` — можно погасить симптом, не поняв причину на другом хосте.
- `UseDNS no` уже стоял — не тратить время на эту гипотезу повторно, если пауза уже после аутентификации.
- Решение специфично для LXC — **не переносить его на полноценные ВМ или физические серверы** без подтверждения той же ошибки 226/NAMESPACE.
- Считать исправлением только сам факт исчезновения задержки недостаточно, если `systemd-logind` продолжает падать — риск возврата проблемы остаётся.

## 7. Проверка результата
```bash
grep -n "pam_systemd" /etc/pam.d/common-session   # строка закомментирована
time ssh root@192.168.200.223                       # без минутной задержки
time ssh root@192.168.200.223 "echo OK && date"      # по-прежнему быстро
```
Подтверждено: после правки новые интерактивные SSH-сессии открываются без
задержки, командная строка появляется сразу.

## 8. Откат (если понадобится)
```bash
sed -i 's/^#[[:space:]]*\(session[[:space:]]\+optional[[:space:]]\+pam_systemd\.so\)/\1/' /etc/pam.d/common-session
```
⚠️ Не откатывать без предварительной проверки состояния `systemd-logind` —
если он по-прежнему падает с `226/NAMESPACE`, задержка вернётся сразу же.

## 9. Риски и ограничения
- Отключение `pam_systemd.so` снижает интеграцию PAM с `systemd-logind` — риск низкий, модуль был `optional`.
- Ручная правка PAM-файла может быть перезаписана `pam-auth-update` при будущих обновлениях — проверять файл после апдейтов пакетов.
- Первопричина (падение `systemd-logind` в контейнере) не устранена, устранён только эффект — статус `completed` относится к симптому, не к первопричине.
- Не проверено поведение после перезагрузки контейнера; не проверено на других LXC с похожими симптомами.

## Открытые вопросы (перенесены из исходника, не решены)
- Нужно ли отдельно чинить работу `systemd-logind` внутри контейнера, а не только гасить симптом отключением модуля?
- Есть ли другие LXC-контейнеры с той же задержкой SSH, где нужно применить то же исправление (только после подтверждения идентичных симптомов)?
