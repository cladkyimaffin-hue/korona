# START-HERE.md

## Назначение

Этот файл является основной точкой входа для ИИ и администратора при работе с доменом `Proxmox`.

Если начинается новый чат и ИИ ещё не знаком со структурой домена, этот файл определяет минимальный порядок инициализации перед поиском ответа.

Общие обязательные правила находятся в:

```text
../AI-INSTRUCTIONS.md
```

Если этот файл противоречит `AI-INSTRUCTIONS.md`, приоритет имеет `AI-INSTRUCTIONS.md`.

---

# 1. Инициализация нового чата

Перед ответом на вопрос, связанный с Proxmox, ИИ должен последовательно ознакомиться с:

```text
Proxmox/START-HERE.md
Proxmox/AI-README.md
Proxmox/00_Meta/INDEX.md
Proxmox/00_Meta/registry.csv
Proxmox/AI-environment_facts-korona-proxmox.md
```

После этого читать только документы, относящиеся к конкретному вопросу.

Не требуется читать весь домен, если вопрос относится к одной ВМ, одному узлу или одной операции.

# 4. Алгоритм поиска

Для любого вопроса использовать следующий порядок:

1. Определить объект.
2. Определить категорию.
3. Открыть `INDEX.md` или `registry.csv`.
4. Найти наиболее подходящий профильный документ.
5. Проверить YAML-метаданные.
6. Проверить `Quick Answers`.
7. Проверить `dont_repeat`.
8. Проверить `related_files`.
9. Проверить `depends_on` и `superseded_by`.
10. Только при необходимости читать документ полностью.
11. Перед изменением конфигурации проверить текущее состояние системы.

# 9. Full Clone

Для production-ВМ документация использует `Full Clone`.

Full Clone означает:

- создаётся независимый диск;
- ВМ не зависит от базового диска шаблона;
- изменения шаблона не изменяют существующую ВМ;
- шаблон может быть удалён после проверки всех зависимостей.

Не предлагать `Linked Clone` для production-ВМ без явного запроса пользователя.

# 10. Изменение дисков

Увеличение виртуального диска в Proxmox и расширение раздела Windows — разные операции.

Сначала:

```text
Proxmox → увеличить виртуальный диск
```

Затем:

```text
Windows → расширить раздел и файловую систему
```

Для VM 2001 документированный пример:

```bash
qm resize 2001 scsi0 +924G
```

Не использовать:

```bash
qm resize 2001 scsi0 +924G --storage ceph-fast
```

# 11. Recovery-раздел Windows

Если Recovery-раздел расположен непосредственно после C:, свободное место может быть недоступно для расширения C:.

Перед удалением Recovery-раздела обязательно:

1. Проверить резервную копию.
2. Определить точный диск.
3. Определить точный номер раздела.
4. Проверить размер.
5. Подтвердить, что раздел действительно Recovery.
6. Получить явное подтверждение пользователя.
7. Только после этого выполнять изменение разметки.

Нельзя предлагать удаление Recovery-раздела только на основании номера раздела.

Использовать:

```powershell
Get-Disk
Get-Partition
Get-Volume
```

# 12. Безопасные проверки Proxmox

Для диагностики использовать readonly-команды.

```bash
qm config <VMID>
qm status <VMID>
pvesm status
```

Для конкретной инфраструктурной проблемы дополнительно использовать профильные команды.

Не выполнять изменение конфигурации только потому, что команда присутствует в документации.

Сначала проверить:

- VM ID;
- имя ВМ;
- узел;
- storage;
- диск;
- состояние ВМ;
- backup;
- зависимости;
- актуальность команды.

---

# 13. Проверка Windows

Для Windows Server использовать, когда необходимо:

```powershell
Get-Disk
Get-Partition
Get-Volume
Get-Service QEMU-GA
```

Не считать результат этих команд известным заранее.

# 14. При диагностике

Разделять:

```text
Факт
Предположение
Проверка
Изменение
Риск
Откат
```

Пример:

```text
Факт:
Документация указывает, что VM 2001 использует Full Clone.

Предположение:
Проблема может быть связана с разметкой диска Windows.

Проверка:
Get-Disk
Get-Partition

Изменение:
Предлагать только после получения результата проверки.

Риск:
Изменение разделов может привести к потере данных.

Откат:
Определить до выполнения операции.
```

# 16. При конфликте документов

Если документы противоречат друг другу:

1. Не выбирать вариант молча.
2. Определить дату/версию документов.
3. Проверить `superseded_by`.
4. Проверить текущую конфигурацию.
5. При наличии свежего вывода команды использовать его как более актуальный источник.
6. Если определить актуальный вариант невозможно — сообщить о конфликте.

# 17. При изменении production

Перед изменением:

1. Определить объект.
2. Проверить текущую конфигурацию.
3. Проверить VM ID.
4. Проверить storage.
5. Проверить backup.
6. Определить необходимость downtime.
7. Определить риск.
8. Подготовить команду.
9. Получить подтверждение для опасной операции.
10. После изменения выполнить проверку.
11. Определить rollback.
12. Обновить документацию.

Разрушительные операции не выполнять без явного подтверждения.

# 18. Быстрые маршруты

### Вопрос: «Как создавали VM 2001?»

Искать:

```text
05_VirtualMachines/
```

Затем документ по VM 2001.

Проверить:

- тип клона;
- порядок развертывания;
- итоговую конфигурацию;
- команды.

### Вопрос: «Зависит ли VM 2001 от шаблона?»

Проверить:

- `ai_summary`;
- `key_takeaways`;
- `dont_repeat`;
- информацию о типе клона.

### Вопрос: «Почему C: не расширяется?»

Искать:

```text
Recovery
Disk 0
Get-Partition
qm resize
расширение раздела
```

### Вопрос: «Какой диск у VM 2001?»

Проверить:

```text
scsi0
VirtIO SCSI
ceph-fast
```

И подтвердить:

```bash
qm config 2001
```

### Вопрос: «Можно ли удалить шаблон 2000?»

Проверить:

- VM 2001 является Full Clone;
- нет других зависимых ВМ;
- VM 2001 успешно запускается;
- диск не является linked/base volume;
- есть backup;
- шаблон больше не используется.

# 20. Главное правило

`Proxmox/START-HERE.md` определяет точку входа в домен.

`Proxmox/AI-README.md` определяет карту знаний.

`Proxmox/00_Meta/registry.csv` определяет машиночитаемый реестр.

`Proxmox/INDEX.md` определяет навигацию.

Профильные документы содержат конкретные решения и историю.

Текущий вывод команд имеет приоритет над устаревшей документацией.

Документация объясняет:

- что уже делали;
- почему было выбрано решение;
- какие варианты отвергли;
- какие команды применяли;
- какие ошибки уже возникали.

Она **не заменяет проверку текущего состояния production**.
