# Клонирование шаблона ВМ 2001 — win-1c-app-01

## Назначение

Документ описывает создание и настройку производственной ВМ Windows Server 2022
для сервера приложений 1С:ERP из шаблона Proxmox VE `2000 (win2022-template)`.

ВМ создаётся только как **полный независимый клон**. Она не использует базовый
диск шаблона и продолжает работать после удаления или изменения шаблона 2000.

## Порядок развертывания

1. Проверить, что шаблон 2000 выключен и имеет статус template.
2. Проверить свободный VM ID `2001`.
3. Создать полный клон на `ceph-fast`.
4. Проверить имя, диск, контроллер и исходную конфигурацию.
5. Увеличить диск с 100 ГБ до 1 ТБ.
6. Установить RAM `163840 MiB`.
7. Установить `24` vCPU.
8. Выполнить `qm config 2001`.
9. Запустить ВМ.
10. Проверить загрузку Windows.
11. Проверить IP-адрес, имя компьютера и QEMU Guest Agent.
12. Удалить или отключить установочные ISO.
13. Проверить структуру диска внутри Windows.
14. Расширить раздел C: только после подтверждения расположения Recovery-раздела.
15. Создать резервную копию ВМ после завершения настройки.

### ASSISTANT
**Шаг 1.1 — Определение идентификаторов (ID), имен и требований к ресурсам для новых ВМ**

Для начала клонирования нам необходимо зафиксировать целевые параметры для каждой из трех виртуальных машин. Исходя из ролей, стандартные 4 ГБ оперативной памяти и 1024 ГБ диска из шаблона могут не подходить (например, для 1С:ERP и терминального сервера 4 ГБ RAM критически мало, а для контроллера домена 1024 ГБ — избыточно и неэффективно для NVMe `ceph-fast`).

**Предлагаемая схема (черновик для согласования):**

| Роль | Предлагаемый ID | Предлагаемое имя (Name) | RAM (МиБ) | Диск (ГБ) | Примечание |
| :--- | :---: | :--- | :---: | :---: | :--- |
| **AD DS** | 2001 | `win-ad-ds-01` | 4096 (или 8192) | 120–150 | Контроллеру домена не нужен диск на 1 ТБ. Уменьшение сэкономит ресурсы `ceph-fast`. |
| **Terminal Server (RDS)** | 2002 | `win-rds-01` | 8192 (или 16384) | 1024 | Для RDS требуется больше RAM. Диск 1 ТБ может быть оправдан для профилей пользователей. |
| **1С:ERP App Server** | 2003 | `win-1c-app-01` | 8192 (или 16384) | 1024 | Для 1С:ERP 4 ГБ RAM недостаточно. Диск 1 ТБ подходит для логов и временных файлов. |

**Важный технический нюанс (Windows):** 
При клонировании мы сможем сразу задать новый объем RAM (через флаг `--memory` в команде `qm clone`). Однако изменение размера диска (уменьшение или увеличение) в Proxmox выполняется командой `qm resize` *после* клонирования, но *до* первого запуска. 
Поскольку это Windows Server, она **не расширит автоматически** раздел C: при первом запуске, даже если мы увеличим размер диска на уровне гипервизора, если в шаблоне не настроен скрипт авто-расширения (например, через cloud-init или задачу в планировщике).

### ASSISTANT
**Шаг 1.2 — Решение вопроса с размером диска при отсутствии скрипта авто-расширения**

Поскольку в шаблоне не настроен скрипт автоматического расширения раздела, любое изменение размера диска на уровне гипервизора (особенно уменьшение) несет высокий риск повреждения файловой системы Windows или невозможности загрузки. 

Однако есть важный технический нюанс: ваше хранилище `ceph-fast` (NVMe) в Proxmox VE по умолчанию использует **тонкое выделение (thin provisioning)**. Это означает, что диск объемом 1024 ГБ **не занимает** 1024 ГБ физического пространства сразу. Он будет занимать только тот объем, который реально записан (для свежего Windows Server 2022 это обычно 30–50 ГБ).

**Наиболее безопасное и профессиональное решение в данной ситуации:**
1. При клонировании **не изменять** размер диска (оставить 1024 ГБ для всех трех ВМ). Это гарантирует, что Windows загрузится без ошибок файловой системы.
2. Реальное потребление места на NVMe будет минимальным благодаря тонкому выделению Ceph.
3. Объем оперативной памяти (RAM) мы изменим сразу на этапе клонирования, так как это полностью безопасно и не влияет на диск.
4. Если в будущем для какой-то ВМ (например, AD DS) потребуется жесткое ограничение максимального размера диска (квота), это можно будет сделать позже через изменение размера диска в Proxmox, но только *после* того, как мы сожмем том внутри самой Windows через `diskmgmt.msc` или PowerShell.

### ASSISTANT
**Шаг 1.2 (корректировка) — Уточнение параметров диска и памяти для клонирования**

Принято. Размер диска шаблона составляет 100 ГБ, а для сервера 1С требуется 1024 ГБ.

**Технический факт:** 
Увеличение размера виртуального диска в Proxmox VE (с 100 ГБ до 1024 ГБ) абсолютно безопасно и выполняется командой `qm resize` *до* первого запуска виртуальной машины. 
Однако, поскольку в шаблоне отсутствует скрипт автоматического расширения раздела, после первого запуска операционная система Windows увидит новый физический диск, но раздел `C:` останется размером ~100 ГБ, а остальное пространство будет отображаться как «нераспределенное». 
**Решение:** Мы увеличим диск на уровне гипервизора при создании ВМ для 1С, а расширение раздела внутри Windows выполним вручную через PowerShell или «Управление дисками» после первого успешного запуска и входа в систему. Это штатная и безопасная процедура.

**Шаг 1.4 — Выбор типа клонирования (Полный или Связанный клон) и ответы на вопросы о зависимостях**

Вы абсолютно верно задали этот вопрос. Вы упустили (или мы еще не зафиксировали) **тип клонирования**. В Proxmox VE существует два принципиально разных режима, и от этого выбора напрямую зависят ответы на ваши вопросы о зависимостях и удалении.

**1. Связанный клон (Linked Clone)**
*   **Как работает:** Создается очень быстро. Клон не копирует данные шаблона, а использует его диск как базовый (read-only) и записывает только свои изменения (дельту).
*   **Зависимость:** Клон **жестко зависит** от шаблона. 
*   **Удаление:** Если вы удалите шаблон (VM 2000), связанный клон **перестанет работать и не загрузится**, так как потеряет базовый диск. Удалить сам клон можно в любой момент, на шаблон это не повлияет.

**2. Полный клон (Full Clone)**
*   **Как работает:** Создается дольше. Proxmox физически копирует все данные диска шаблона на новое хранилище (в нашем случае `ceph-fast`).
*   **Зависимость:** Клон становится **полностью независимым** от шаблона. Это две разные виртуальные машины.
*   **Удаление:** Вы можете удалить шаблон (VM 2000) в любой момент, и полные клоны продолжат работать без каких-либо проблем. Удаление клона также никак не затрагивает шаблон.

**Рекомендация:** Для продакшн-серверов (AD DS, RDS, 1С:ERP) **всегда используется Полный клон (Full Clone)**. Связанные клоны обычно применяют только для быстрого тестирования.
