# Добавление дополнительного SSID (RSK) на точках доступа MikroTik (Т2, Т1-Т6)

## Цель и исходные условия
Требовалось добавить на MikroTik дополнительную Wi-Fi-сеть рядом с существующими. Настройку начали на точке Т2 (192.168.200.32) через терминал. Для новой сети RSK требовались диапазоны 2,4 и 5 ГГц и полный доступ к локальной сети через тот же мост, что и основные SSID.
Позже пользователь сообщил, что настройка второго SSID внесена на все точки доступа Т1–Т6. Для Т1 и Т3–Т6 IP-адреса, версии RouterOS и фактический вывод конфигурации не приводились.

## Итоговое состояние
- На Т2 подтверждены RouterOS 7.23.2, модель RBcAPGi-5acD2nD (cAP ac), пакет `wifi-qcom-ac` и локальное управление через `/interface wifi`.
- На Т2 существовали SSID `Korona-wifi-2` и `Korona-wifi-5` на интерфейсах `wifi-2` и `wifi-5`; оба интерфейса были привязаны к `bridge1`.
- Для RSK созданы профили `sec-rsk` и `conf-rsk`, виртуальные интерфейсы `wifi-2-rsk` и `wifi-5-rsk`, а новые интерфейсы добавлены в `bridge1`. Пользователь подтвердил выполнение команд.
- Первоначальный пароль `VUE7erzXra#` был заменён на `VUE7erzXra`. После сообщения пользователя «все заработало» работу RSK сочли успешной.
- На момент проверки `wifi-2-rsk` имел флаги `BR`, а `wifi-5-rsk` — только `B`, без `R`. Позднейшего подтверждения, что интерфейс 5 ГГц стал `RUNNING`, в переписке нет.
- Команды для создания сети `Korona.ru` были предложены, но их выполнение пользователь не подтверждал. Указанный в них пароль — плейсхолдер `****`, а не заданный реальный пароль.
- Пользователь сообщил, что настройка второго SSID выполнена на Т1–Т6, но не уточнил, относится ли это к RSK, и не подтвердил создание `Korona.ru` на всех точках.

## Важные решения и причины
1. **Использовать `/interface wifi`, а не `/interface wireless`.** Установлен пакет `wifi-qcom-ac` версии 7.23.2; команда `/interface wireless print` завершилась ошибкой `bad command name wireless`.
2. **Создавать виртуальные интерфейсы на обоих радиомодулях.** Для 2,4 и 5 ГГц использованы мастера `wifi-2` и `wifi-5`; одному профилю конфигурации назначено имя SSID `RSK`.
3. **Добавить виртуальные интерфейсы в `bridge1`.** Так были включены новые интерфейсы в тот же мост, что и основные Wi-Fi-интерфейсы, для доступа к локальной сети.
4. **Заменить пароль с `VUE7erzXra#` на `VUE7erzXra`.** В переписке это объяснили тем, что `#` в терминале RouterOS мог быть воспринят как начало комментария и привести к обрезке пароля. Это объяснение не подтверждено проверкой сохранённого значения или логами. После смены пароля пользователь сообщил об успешной работе, но точная причина исходного сбоя не установлена.

## Команды и конфигурации

### Диагностика Т2
```routeros
/system resource print
/system package print where name~"wifi|wireless"
/interface wireless print
/interface wifi print
/caps-man manager print
/interface bridge port print where interface~"wifi"
```
Результаты подтвердили RouterOS 7.23.2, пакет `wifi-qcom-ac`, интерфейсы `wifi-2` и `wifi-5`, а также мост `bridge1`. Команды `/interface wireless print` и `/caps-man manager print` вернули *bad command name*.

### Создание профилей RSK
В переписке был предложен следующий шаблон; `****` требовалось заменить паролем перед выполнением:
```routeros
/interface wifi security
add name=sec-rsk authentication-types=wpa2-psk,wpa3-psk passphrase="****"

/interface wifi configuration
add name=conf-rsk ssid=RSK security=sec-rsk
```
Позже предложено изменить пароль:
```routeros
/interface wifi security set sec-rsk passphrase="VUE7erzXra"
```
В качестве команды отката было указано:
```routeros
/interface wifi security set sec-rsk passphrase="VUE7erzXra#"
```
Фактическое первоначальное значение пароля в профиле не проверено.

### Создание виртуальных интерфейсов RSK
```routeros
/interface wifi add name=wifi-2-rsk master-interface=wifi-2 configuration=conf-rsk disabled=no
/interface wifi add name=wifi-5-rsk master-interface=wifi-5 configuration=conf-rsk disabled=no
/interface bridge port add bridge=bridge1 interface=wifi-2-rsk
/interface bridge port add bridge=bridge1 interface=wifi-5-rsk
```
Проверки, предложенные в переписке:
```routeros
/interface wifi print where name~"rsk"
/interface bridge port print where interface~"rsk"
/log print where topics~"wifi" limit=50
/ip dhcp-server lease print where active=yes
```
Команда просмотра Wi-Fi-логов была предложена, но её результат в переписке отсутствует. Вывод DHCP leases был пустым.

### Команды, которые сработали (проверено)

```routeros
# Создание профиля безопасности
/interface wifi security add name=sec-rsk authentication-types=wpa2-psk,wpa3-psk passphrase="VUE7erzXra"
# Создание профиля конфигурации
/interface wifi configuration add name=conf-rsk ssid=RSK security=sec-rsk

# Создание виртуальных интерфейсов
/interface wifi add name=wifi-2-rsk master-interface=wifi-2 configuration=conf-rsk disabled=no
/interface wifi add name=wifi-5-rsk master-interface=wifi-5 configuration=conf-rsk disabled=no

# Добавление в бридж (bridge1)
/interface bridge port add bridge=bridge1 interface=wifi-2-rsk
/interface bridge port add bridge=bridge1 interface=wifi-5-rsk
```

### Диагностика DHCP и маршрутизации
Были запрошены, но не выполнены или не приведены в переписке:
```routeros
/ip dhcp-server print
/interface bridge port print
/ip address print
/ip route print
```

### Предложенный, но не подтверждённый блок для Korona.ru
Пароль не задан; `****` — плейсхолдер, и его нельзя использовать как реальный пароль без явного намерения:
```routeros
/interface wifi security add name=sec-korona authentication-types=wpa2-psk,wpa3-psk passphrase="****"
/interface wifi configuration add name=conf-korona ssid=Korona.ru security=sec-korona
/interface wifi add name=wifi-2-korona master-interface=wifi-2 configuration=conf-korona disabled=no
/interface wifi add name=wifi-5-korona master-interface=wifi-5 configuration=conf-korona disabled=no
/interface bridge port add bridge=bridge1 interface=wifi-2-korona
/interface bridge port add bridge=bridge1 interface=wifi-5-korona
```

## Ошибки, риски и чего не повторять
- Не запускать повторно команды `add` без проверки существующих объектов. Создание профилей, виртуальных интерфейсов и портов моста неидемпотентно и может привести к дубликатам.
- Не оставлять `****` в команде создания профиля безопасности, если это не желаемый пароль. В блоке Korona.ru реальный пароль не был предоставлен.
- Не считать причину сбоя с `#` доказанной. В переписке предположили, что символ был интерпретирован как комментарий, но это не проверили. Изменение пароля и последующая работа сети зафиксированы, однако причинная связь не установлена.
- Не считать, что успешное подключение подтвердило работу обоих диапазонов. В проверке `wifi-5-rsk` не имел флага R; позднее отдельная проверка 5 ГГц не приведена.
- Не считать, что добавление в мост доказано выводом портов. Команды добавления были предложены и пользователь сообщил, что всё сделал, но вывод `/interface bridge port print where interface~"rsk"` отсутствует.
- Команды `/interface wireless print` и `/caps-man manager print` на Т2 завершились ошибками *bad command name*; для этой конфигурации использовали `/interface wifi`.
- Вывод `/ip dhcp-server lease print where active=yes` был пустым. Это само по себе не доказывает неисправность DHCP: DHCP-сервер мог находиться на другом устройстве, но это в переписке не подтверждено.

## Открытые вопросы и проверки
**Не подтверждено**
- Был ли пароль в профиле `sec-rsk` при первоначальном создании обрезан до VUE7erzXra.
- Что именно вызвало отсутствие доступа в интернет и какое действие устранило проблему.
- Получал ли клиент IP-адрес, шлюз и DNS во время сбоя.
- Запущен ли сейчас виртуальный интерфейс `wifi-5-rsk`.
- Внесена ли на Т1–Т6 конфигурация RSK или другая конфигурация второго SSID; фактические конфигурации остальных точек не показаны.
- Создавалась ли сеть Korona.ru после того, как для неё был предложен блок команд.

**Требует проверки**
- На Т2: состояние `wifi-5-rsk`, наличие обоих RSK интерфейсов в `bridge1` и фактические параметры профиля безопасности.
- На Т1–Т6: единообразие SSID, профилей безопасности, привязки к мастерам и мосту; для Т1 и Т3–Т6 в переписке нет IP-адресов и командной диагностики.
- Если нужно развернуть Korona.ru, сначала задать реальный пароль и проверить, нет ли уже объектов с именами `sec-korona`, `conf-korona`, `wifi-2-korona` и `wifi-5-korona`.

## Следующие действия
- Перед повторным созданием любых объектов проверить текущую конфигурацию на каждой точке и не выполнять `add` повторно вслепую.
- Проверить `wifi-5-rsk` и записи виртуальных интерфейсов в `bridge1` на Т2.
- Если требуется Korona.ru, уточнить пароль и подтвердить, на каких именно точках её нужно создавать.

## Краткое резюме
На Т2 (192.168.200.32) создали SSID RSK в диапазонах 2,4 и 5 ГГц и добавили виртуальные интерфейсы в `bridge1`; пользователь сообщил, что в итоге всё заработало. Причину первоначального сбоя точно не установили, а состояние 5-ГГц-интерфейса осталось непроверенным. Пользователь сообщил о настройке второго SSID на Т1–Т6, но создание Korona.ru не подтверждено; пароль для этой сети в предложенном блоке остался плейсхолдером.

## Проверка полноты
- **Команды и реальные значения:** сохранены, включая адрес Т2, модель, версию RouterOS, имена интерфейсов, мост, SSID, пароли и диагностические команды. Плейсхолдер `****` отдельно отмечен.
- **Причины ключевых решений:** сохранены; предполагаемая роль символа `#` помечена как неподтверждённая.
- **Важные ошибки и результаты диагностики:** сохранены, включая *bad command name*, пустой вывод DHCP leases и отсутствие флага R у `wifi-5-rsk`.
- **Незавершённые вопросы и неопределённости:** перечислены; проверка DHCP, маршрутизации, 5 ГГц, остальных точек и Korona.ru не подтверждена.
