# AI-NEW-CHAT-CONTEXT.md — контекст для новых чатов по внесению данных в korona

Этот файл читается первым в любом новом чате, который вносит данные в репозиторий
`cladkyimaffin-hue/korona`. Он не заменяет протоколы репозитория, а задаёт порядок работы
и формат результата. Если что-то здесь противоречит `AI-INSTRUCTIONS.md` или протоколу
домена, приоритет у них (см. раздел 2).

---

## 1. Репозиторий: что это и как устроено

- GitHub: `cladkyimaffin-hue/korona`, ветка `main`. Репозиторий **публичный**. Решение
  администратора: видимость не меняется.
- Домены верхнего уровня: `Proxmox/` и `MikroTik/`. В корне репозитория также лежат общий
  `SCHEMA.md`, `Chat-Qwen/` (сырые выгрузки чатов, не домен конвейера) и `agent/` (назначение не
  описано, без запроса администратора не трогать). Имена папок проверяй по листингу каталога, а не
  по памяти: раньше у папки `MikroTik` в имени был конечный пробел, сейчас его нет.
- Метаданные документов определяет общий `SCHEMA.md` в корне. У каждого домена свой независимый
  набор служебных файлов в `<домен>/00_Meta/`: `SCHEMA.md` (только доменные дополнения), `TAGS.md`,
  `registry.csv`, `CHANGELOG.md`, `CONFLICTS.md`, `TEMPLATES/`. Реестр, теги и ID одного домена не
  переиспользуются в другом.
- Служебные файлы существуют в одном экземпляре (протокол, §22б). Копии в `99_Archive/`
  и других папках не создаются.
- Корень домена содержит `START-HERE.md`, `AI-README.md`, `INDEX.md`, `AI-environment_facts-*.md`;
  в `Proxmox/` есть и `COMMANDS.md` (справочник команд с классами [R]/[W]/[D]); в `MikroTik/` его пока нет.

## 2. Порядок чтения перед любым изменением

1. `AI-INSTRUCTIONS.md` (корень) — общие правила, раздел 8а (протокол конвейера).
2. Протокол добавления данных:
   - `AI-ADD-DATA-Cloud-INSTRUCTIONS.md` — для облачных данных и вообще по умолчанию,
     если сомнений нет;
   - `AI-ADD-DATA-INSTRUCTIONS.md` — только если администратор явно указал его.
   Если тип данных неясен — спроси, не угадывай.
3. Общий `SCHEMA.md` из корня и служебные файлы домена: `<домен>/START-HERE.md`, `AI-README.md`,
   `00_Meta/SCHEMA.md`, `TAGS.md`, `registry.csv`, `INDEX.md`, `AI-environment_facts-*.md`,
   `CONFLICTS.md`, `CHANGELOG.md`.
4. Минимум 2–3 похожих документа того же домена.

**Перед правкой любого файла перечитай его актуальное состояние из `main`.** Файлы меняют
параллельные сессии и администратор вручную. Копия из начала диалога может быть устаревшей.
Технически надёжнее всего:

```bash
git clone --depth 1 https://github.com/cladkyimaffin-hue/korona.git
```

`api.github.com` без токена часто отдаёт `rate limit exceeded`; `raw.githubusercontent.com`
и `git clone` работают стабильнее.

## 3. Что вносить и как: правило полного файла

**Основной формат результата — полный файл на замену**, а не фрагменты.

- Изменил файл — отдай его целиком, с путём от корня репозитория. Пользователь заменяет
  файл целиком и не ищет место вставки.
- Фрагменты и «вставь после строки N» не отдавать. Это ошибка формата.
- **Исключение:** строка, которую нужно добавить в самый конец файла (например, строку в
  `CHANGELOG.md` или новую строку в `registry.csv`), можно отдать одной строкой с указанием
  «добавить в конец». Ничего другого в конец не дописывать.
- Файлы, которые не менялись, не отдавать.
- Результат (когда записи в репозиторий нет, см. §4) — файлы в `/mnt/user-data/outputs/<название>/`
  с сохранением путей, затем `present_files`. Не ограничивайся текстом в чате, если файлов больше одного.

## 4. Запись в репозиторий

- Если коннектор GitHub даёт запись, **каждое изменение делается в отдельной ветке от актуального
  `main` и в отдельном PR**; в `main` напрямую не писать. Форма создания PR из чата у пользователя не
  отображается: вместо неё дай ссылку `https://github.com/cladkyimaffin-hue/korona/compare/main...<ветка>`,
  заголовок и описание PR в блоках кода. PR создаёт и сливает пользователь (пишет «слил»); после
  этого проверь `merged_at` через `list_pull_requests`.
- API правит файл только полной перезаписью (`create_or_update_file` с `sha` или `push_files`, без
  патчей), поэтому перед правкой перечитай файл из `main`, а после каждого коммита сверь diff с `main`
  через `get_commit`: статистика +/− должна совпасть с тем, что ты менял, любое лишнее изменение —
  ошибка. При переписывании большого файла легко внести опечатку.
- Коммиты в стиле `docs(область): суть`, в теле — источник.
- `search_code` в этом репозитории ничего не находит (индекс), на него не полагайся.
- Коннектор может вернуть `403 Resource not accessible by integration`. Это значит, что записи нет.
  Тогда отдавай файлы для ручной замены (§3) и **не пиши «записано»**.
- Перед записью покажи план: какие файлы меняются, зачем, и что проверено. Запись выполняй только
  после подтверждения пользователя, если он не дал прямого указания записать.
- Если `main` изменился с момента чтения, а файл тоже менялся — собери версию поверх
  актуальной, а не поверх своей копии. Не перезаписывай чужие правки.

## 5. Проверки перед выдачей

Перед выдачей файлов проверь:

- **Фронтматтер** проходит YAML-парсер. Строковые значения, содержащие `:`, `#`, `[`, `]`,
  `{`, `}`, `|`, `>`, в двойных кавычках. Без кавычек фронтматтер ломается (уже была такая
  ошибка в `1c-slow-public-network-2026-10-15.md`).
- **Блоки кода** открыты и закрыты, у каждого указан язык. Голые слова `text`, `bash`,
  `powershell` на отдельной строке — признак потерянных маркеров.
- **Таблицы** в markdown-синтаксисе с `|`, после каждой таблицы пустая строка. Табуляция
  не таблица.
- **Теги** есть в `TAGS.md`, не дублируются, не стоят одновременно в двух группах.
- **`document_id`** уникален и есть в `registry.csv`; `registry.title` == `frontmatter.title`
  == H1; `registry.category` == `frontmatter.category` == папка из `registry.path`.
- **Категория:** папка верхнего уровня домена или одна документированная подпапка
  (не глубже одного уровня, описана в `AI-README.md`). Пример: `08_Monitoring/Zabbix`.
- **Ссылки** в `INDEX.md` и `related_files` указывают на существующие файлы. Русские пути
  в markdown-ссылках кодируются (`(` → `%28`, `)` → `%29`, пробел → `%20`, кириллица —
  UTF-8 percent-encoding). Запятые в именах файлов не использовать.
- **`CHANGELOG.md`:** строка `ГГГГ-ММ-ДД | тип | что сделано | кем/чем`. Тип — из шапки файла.
  Обычное обновление содержимого документа в `CHANGELOG` не пишется.
- **`CONFLICTS.md`:** если найдено противоречие между источниками — запись в очередь, а не
  тихая правка одного из документов.
- **Секреты:** в файлах нет паролей, токенов, приватных ключей и логинов. Схемы с
  учётными данными переносятся без них. Фраза «хранить в Vaultwarden» допустима.

Минимальный автоматический аудит (запускать из папки домена, например `Proxmox/`):

```python
import csv, re, os, glob, yaml
rows = list(csv.DictReader(open("00_Meta/registry.csv", encoding="utf-8")))
ids = [r["document_id"] for r in rows]
print("дубли ID:", {i for i in ids if ids.count(i) > 1} or "нет")
for r in rows:
    if not os.path.exists(r["file_path"]):
        print("нет файла:", r["document_id"], r["file_path"])
for f in glob.glob("**/*.md", recursive=True):
    t = open(f, encoding="utf-8").read()
    if t.count("```") % 2:
        print("незакрытый блок кода:", f)
    m = re.match(r"---\n(.*?)\n---\n", t, re.S)
    if m:
        try:
            yaml.safe_load(m.group(1))
        except Exception as e:
            print("YAML:", f, str(e).splitlines()[0])
```

Скрипт не заменяет проверку человеком, но ловит типичные ошибки этого репозитория.

## 7. Типичные ошибки этого репозитория (не повторять)

- Фронтматтер без кавычек в строках с `:` — YAML не парсится.
- Блоки кода с потерянными маркерами — весь последующий текст рендерится как код.
- Таблицы с табуляцией вместо `|` — не рендерятся; строка сразу после таблицы без пустой
  строки становится строкой таблицы.
- `INDEX.md` обрывался посреди блока кода (Decision Tree). Перед выдачей проверь, что файл
  полный и все блоки закрыты.
- `category` подпапкой без описания в `AI-README.md` — не делать.
- Копия служебного файла в `99_Archive/` — дубль источника истины.
- Заголовок в `registry.csv` и во frontmatter расходятся (была такая ошибка с `AUTOSTART`).
- Опечатка в H1 протокола (`Cloud- INSTRUCTIONS`): имя файла и заголовок должны совпадать.
- Номера строк и «вставь после строки N» — ненадёжны, так как файлы меняются. Использовать
  полный файл.

## 8. Формат ответа пользователю

Пользователь предпочитает:

- Русский язык.
- Маленькие шаги, с явным уровнем уверенности по каждому выводу (VERIFIED — подтверждено
  командой или документом; INFERRED — вывод; UNKNOWN — не известно).
- Без изменений «втихую»: каждое изменение названо и объяснено.
- Лог того, что сделано и что показало.
- Нейтральный, фактический язык в деловых документах: проблемы описываются как задачи,
  а не как претензии.
- Если данные не подтверждены — прямо написать «NEEDS HUMAN VERIFICATION» и перечислить
  вопросы администратору.

В конце выдачи обязательно: какие файлы отданы, что проверено, что не проверено, что
требует решения пользователя.
