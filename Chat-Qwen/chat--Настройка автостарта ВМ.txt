**Объяснение / действие:**  
Применяем согласованные параметры `order` (порядок) и `up` (задержка в секундах) к подтверждённым объектам. Это гарантирует, что при перезагрузке узла Proxmox сначала поднимется AD, затем TC, затем Srv1c, и только после них — контейнеры passwd и zabbix.

**Сверка с environment_facts:**  
Объекты и их роли подтверждены на предыдущем шаге (VM 2002=AD, VM 2003=TC, VM 2001=Srv1c, CT 600=passwd, CT 700=zabbix). Параметр `onboot: 1` для них уже установлен.

**Как проверить результат:**  
Выполните в консоли Proxmox следующие три блока команд (они укладываются в лимит безопасных действий для подробного режима).

1. Применить настройки к виртуальным машинам:
```bash
qm set 2002 -startup order=1,up=120; qm set 2003 -startup order=2,up=60; qm set 2001 -startup order=3,up=120
```

2. Применить настройки к LXC-контейнерам:
```bash
pct set 600 -startup order=4,up=60; pct set 700 -startup order=5,up=0
```

3. Проверить итоговую конфигурацию:
```bash
for id in 2002 2003 2001; do echo "VM $id:"; qm config $id | grep '^startup:'; done; for id in 600 700; do echo "CT $id:"; pct config $id | grep '^startup:'; done
```

**Риск:**  
Низкий. Изменение параметра `startup` не влияет на текущую работу запущенных систем и вступает в силу только при следующей перезагрузке узла.

**Идемпотентность:**  
Идемпотентно. Повторный запуск этих команд просто перезапишет значение параметра `startup` на то же самое, не создавая дубликатов или ошибок.

**Откат:**  
Удаление параметра (возврат к параллельному запуску, если потребуется):  
`qm set <VMID> -delete startup`  
`pct set <CTID> -delete startup`

**Уверенность:**  
Высокий. Используются штатные, документированные команды управления Proxmox VE (`qm set` и `pct set`), поведение которых предсказуемо.
