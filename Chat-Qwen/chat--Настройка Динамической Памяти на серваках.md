### 1. Поиск исполняемого файла службы балуна на ISO virtio-win
Выполните в PowerShell (от имени администратора) внутри ВМ, чтобы найти точный путь к `blnsvr.exe` для вашей версии Windows:
```powershell
Get-ChildItem -Path D:\ -Recurse -Filter 'blnsvr.exe' -ErrorAction SilentlyContinue | Select-Object FullName
```
*(Где `D:\` — буква диска, на котором смонтирован ISO-образ virtio-win)*

### 2. Создание службы BalloonService
Используя найденный путь (например, для Windows Server 2025 x64 это `D:\Balloon\2k25\amd64\blnsvr.exe`), создайте службу:
```powershell
sc.exe create BalloonService binPath= "D:\Balloon\2k25\amd64\blnsvr.exe" start= auto
```

### 3. Запуск и проверка службы
```powershell
Start-Service -Name BalloonService
Get-Service -Name BalloonService
```
*(Статус должен быть `Running`)*

### 4. Требования на стороне гипервизора Proxmox
В конфигурации виртуальной машины должен быть включен QEMU Guest Agent. Проверить это можно командой на хосте Proxmox:
```bash

```
В выводе должна присутствовать строка:

**Почему это важно для мониторинга:**  
Без запущенной службы `BalloonService` и `QEMU Guest Agent` Proxmox (и Zabbix, если он опрашивает гипервизор) показывает не реальное использование памяти внутри гостевой ОС, а объем памяти, зарезервированный процессом QEMU на хосте (включая накладные расходы гипервизора, видеопамять и буферы), что часто выглядит как "переполнение" (>100%). После выполнения этих команд метрики памяти начинают отображаться корректно.

### ASSISTANT
В Proxmox память для **LXC-контейнеров** (в отличие от KVM-виртуальных машин) **изначально работает динамически** на уровне cgroups ядра Linux . 

Значение, которое вы видите в параметре `memory` (например, `memory: 2048`), — это **не статическое резервирование**, а **верхний лимит** (максимальный потолок), который контейнер может использовать. Если ваш Zabbix внутри контейнера 700 использует только 500 МБ, остальные 1548 МБ свободно доступны хост-системе Proxmox для других задач или дискового кэша .

Если вам нужно **изменить этот лимит "на лету"** (без перезагрузки контейнера), выполните на хосте Proxmox следующую команду:

```bash
pct set 700 -memory <новый_лимит_в_МБ>
```

**Примеры:**
- Установить лимит в 2 ГБ: `pct set 700 -memory 2048`
- Установить лимит в 4 ГБ: `pct set 700 -memory 4096`

Это изменение применяется мгновенно через механизмы cgroups, перезагрузка контейнера не требуется.

### Как проверить текущее состояние:
1. **Посмотреть текущую конфигурацию контейнера:**
   ```bash
   cat /etc/pve/lxc/700.conf
   ```
   (Ищите строку `memory: ...`)

2. **Посмотреть реальное потребление памяти изнутри контейнера:**
   ```bash
   pct enter 700
   free -h
   ```
   Вы увидите, что значение `used` будет соответствовать реальным потребностям Zabbix, а не заданному лимиту.

### ⚠️ Важное примечание:
Если вам кажется, что память всё равно расходуется "статически", убедитесь, что в файле `/etc/pve/lxc/700.conf` **нет ручных параметров cgroup**, которые могут жестко фиксировать память (например, строк вида `lxc.cgroup.memory.limit_in_bytes` или `lxc.cgroup2.memory.max`). В стандартной конфигурации достаточно только параметра `memory: <значение>`, и Proxmox сам управляет им динамически. 

*(Примечание: Технология Memory Ballooning, о которой шла речь ранее, применяется **только для KVM-виртуальных машин** , для LXC используется нативное динамическое управление памятью ядра Linux).*

Виртуальная машина **2001 (Srv1c / win-1c-app-01)** — это полноценная KVM-виртуальная машина с Windows, а не LXC-контейнер. Поэтому механизм динамической памяти здесь устроен иначе, чем в LXC 700.

Для KVM-машин в Proxmox используется технология **Memory Ballooning** (раздувание шарика памяти). Она работает в связке с **QEMU Guest Agent** и драйвером **VirtIO Balloon** внутри гостевой ОС.

### Как это должно быть устроено в ВМ 2001:

1. **На уровне гипервизора (Proxmox):**
   В конфигурации ВМ (`/etc/pve/qemu-server/2001.conf`) должны быть заданы два параметра:
   - `memory: <максимум>` (например, `8192` для 8 ГБ) — это верхний потолок, который ВМ может использовать.
   - `balloon: <минимум>` (например, `2048` для 2 ГБ) — это минимальный объем памяти, который гипервизор гарантирует ВМ. Если ВМ простаивает, Proxmox может "отобрать" неиспользуемую память и отдать её другим задачам на хосте.
   - `agent: 1` — обязательное включение QEMU Guest Agent для связи с гостевой ОС.

   *Команда для проверки:*
   ```bash
   qm config 2001 | grep -E 'memory|balloon|agent'
   ```

2. **На уровне гостевой ОС (Windows Server):**
   Чтобы гипервизор мог управлять памятью, внутри Windows должны быть выполнены те же действия, что мы делали для ВМ 2002:
   - Установлен и запущен **QEMU Guest Agent**.
   - Установлен драйвер **VirtIO Balloon**.
   - Создана и работает служба **BalloonService** (`blnsvr.exe`), которая сообщает гипервизору, сколько памяти можно временно изъять.

### Почему сейчас она может казаться "статической":
Вы ранее упоминали: *"На 2001 (win-1c) я отмонтировал VirtIO"*. 
Если образ `virtio-win.iso` отключен, а служба `BalloonService` внутри Windows не настроена или не запущена, то:
- Гипервизор **не может** изъять неиспользуемую память.
- Proxmox (и Zabbix, если он опрашивает гипервизор) показывает не реальное потребление 1С-сервера, а **Host memory usage** — объем памяти, который процесс QEMU забрал у хоста при запуске (включая кэш Windows и накладные расходы). Это значение остается высоким и статичным, даже если 1С сейчас не нагружена.

### Что нужно сделать, чтобы включить динамическую память в ВМ 2001:

**Шаг 1. Настроить лимиты на хосте Proxmox** (пример для минимума 2 ГБ и максимума 8 ГБ):
```bash
qm set 2001 -memory 8192 -balloon 2048 -agent enabled=1
```
*(Изменения применяются на лету, но для активации ballooning может потребоваться перезагрузка ВМ, если драйвер не был инициализирован).*

**Шаг 2. Внутри ВМ 2001 (Windows):**
1. Снова подключите ISO-образ `virtio-win.iso` к виртуальному CD-приводу ВМ 2001 через интерфейс Proxmox.
2. Откройте PowerShell от имени администратора и найдите диск с ISO (как мы делали ранее, например, диск `D:` или `E:`).
3. Убедитесь, что служба QEMU-GA работает: `Get-Service QEMU-GA`
4. Найдите и установите службу Balloon для вашей версии Windows (например, для Server 2022 это `2k22\amd64`):
   ```powershell
   sc.exe create BalloonService binPath= "D:\Balloon\2k22\amd64\blnsvr.exe" start= auto
   Start-Service -Name BalloonService
   Get-Service -Name BalloonService
   ```
