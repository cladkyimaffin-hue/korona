### ASSISTANT
Чтобы посмотреть порты и подключенные к ним устройства в MikroTik, можно использовать как командную строку (CLI), так и графический интерфейс WinBox. Ниже приведены основные способы.

### 1. Просмотр физических портов и их состояния
**Через CLI (Terminal):**
```routeros
/interface ethernet print
```
*Покажет список всех физических портов (ether1, ether2 и т.д.), их статус (flags: X означает отключен, R означает running/активен), текущую скорость (rate) и имя.*

Чтобы следить за состоянием конкретного порта в реальном времени:
```routeros
/interface ethernet monitor ether2
```
*(Нажмите `Ctrl+C` для выхода из режима мониторинга).*

**Через WinBox:**
Перейдите в меню **Interfaces**, дважды кликните на нужный порт (например, `ether2`) и откройте вкладку **Monitor**. Там будет виден статус линка, скорость, дуплекс и MAC-адрес.

---

### 2. Просмотр устройств, подключенных к портам (MAC-адреса)
Если ваши порты объединены в мост (Bridge), что является стандартной настройкой для локальной сети, MikroTik запоминает, какой MAC-адрес через какой порт пришел.

**Через CLI:**
```routeros
/interface bridge host print
```
*Покажет таблицу: MAC-адрес устройства, интерфейс (порт), на котором он замечен, и статус (например, `forwarding`).*

Чтобы отфильтровать по конкретному порту:
```routeros
/interface bridge host print where interface=bridge1
```
*(Замените `bridge1` на имя вашего моста или конкретного порта, например `ether3`).*

**Через WinBox:**
Перейдите в **Bridge** → вкладка **Hosts**. Здесь вы увидите список всех MAC-адресов и портов (Interface), на которых они активны.

---

### 3. Просмотр IP- и MAC-адресов подключенных клиентов
Чтобы понять, кто именно подключен (какое устройство), лучше всего посмотреть таблицу DHCP-аренд и ARP.

**Через CLI:**
```routeros
/ip dhcp-server lease print
```
*Покажет все выданные IP-адреса, соответствующие MAC-адреса, имена устройств (Host Name) и статус (bound = активно подключен).*

```routeros
/ip arp print
```
*Покажет текущую таблицу ARP: какой IP-адрес какому MAC-адресу соответствует и на каком интерфейсе он находится.*

**Через WinBox:**
Перейдите в **IP** → **DHCP Server** → вкладка **Leases**. 
Зеленые строки со статусом `bound` означают активно подключенные устройства. Вы можете увидеть их имя (если устройство его передает), MAC и IP.

---

### 4. Сканирование порта на наличие MAC-адресов (если устройство не получает DHCP)
Если устройство имеет статический IP или не запрашивает DHCP, его можно найти через сканирование MAC-адресов на конкретном порту.

**Через CLI:**
```routeros
/tool mac-scan interface=ether3
```
*(Замените `ether3` на нужный порт. Нажмите `Ctrl+C` для остановки).*

**Через WinBox:**
Перейдите в **Tools** → **MAC Scan**, выберите нужный интерфейс в выпадающем списке и нажмите **Start**.

---

### Краткий чек-лист для быстрой диагностики:
1. `/interface print` → порт вообще включен и активен (флаг `R`)?
2. `/interface bridge host print` → видит ли коммутатор MAC-адрес на этом порту?
3. `/ip dhcp-server lease print` → получил ли этот MAC-адрес IP от роутера?

```routeros
# Проверка выданных DHCP-адресов (если устройство запрашивает IP автоматически)

# Проверка ARP-таблицы (покажет IP, даже если он задан статически)
```

### 4. Что с ним можно сделать (если устройство нежелательное)
Если вы не знаете это устройство или оно подключено несанкционированно, у вас есть два основных пути:

**Вариант А: Полностью отключить порт** (физически разорвет соединение для всего, что подключено к sfp11):
```routeros
/interface set sfp11 disabled=yes
```
*(Чтобы включить обратно: `/interface set sfp11 disabled=no`)*

**Вариант Б: Заблокировать доступ в сеть только этому устройству** (порт останется работать, но трафик с этого MAC будет отброшен):
```routeros
/ip firewall filter add chain=forward src-mac-address=58:04:4F:EE:25:92 action=drop comment="Block unknown TP-Link device"
/ip firewall filter add chain=input src-mac-address=58:04:4F:EE:25:92 action=drop
```

### 🔍 Шаг 3: Самая вероятная причина — VLAN

SX3008F — управляемый коммутатор. Судя по Torch, он шлет трафик с **VLAN 40**. Если его management VLAN изменился на 40, то:
- Его IP `192.168.202.202` теперь находится **внутри VLAN 40**
- Порт `sfp11` на MikroTik, скорее всего, настроен как **access** (без тегов) или на другой VLAN, поэтому вы не видите коммутатор

**Проверьте настройки порта sfp11:**
```routeros
/interface ethernet print where name=sfp11
/interface bridge port print where interface=sfp11
/interface vlan print where interface=sfp11
```

**Решение — добавить VLAN 40 на MikroTik и назначить ему IP из подсети коммутатора:**

```routeros
# Создать VLAN интерфейс на sfp11
/interface vlan add interface=sfp11 vlan-id=40 name=vlan40-sfp11

# Добавить его в мост (если нужно) или назначить IP напрямую
/ip address add address=192.168.202.254/24 interface=vlan40-sfp11
```

После этого попробуйте пингануть:
```routeros
/ping 192.168.202.202
```

### ASSISTANT
Нет, добавление второго IP-адреса на интерфейс моста (`bridge1`) в MikroTik RouterOS — это **безопасная и стандартная операция**. 

Существующая связь с MikroTik **не оборвётся**, текущие настройки маршрутизации и DHCP не будут перезаписаны или отключены. RouterOS позволяет назначать множество IP-адресов на один и тот же интерфейс. Система просто начнёт отвечать на запросы как по старому адресу, так и по новому.

Ниже приведён безопасный пошаговый план действий в соответствии с протоколом.

---

### Шаг 1. Проверка текущих IP-адресов на мосту
Прежде чем добавлять адрес, убедимся, что `192.168.0.2/24` ещё не назначен на `bridge1` (чтобы избежать ошибки дублирования).

**Команда для выполнения:**
```routeros
/ip address print where interface=bridge1
```

**Как проверить результат:** 
Вывод покажет список всех IP-адресов, привязанных к `bridge1`. Убедитесь, что `192.168.0.2` в списке отсутствует.

**Уверенность:** Высокий (стандартная read-only команда диагностики).

---

### Шаг 2. Добавление второго IP-адреса
Если адреса `192.168.0.2` нет в списке, выполняем добавление.

**Команда для выполнения:**
```routeros
/ip address add address=192.168.0.2/24 interface=bridge1 comment="Management SX3008F"
```

**Сверка с environment_facts:** 
Интерфейс `bridge1` подтверждён как активный и содержащий порт `sfp11` (из предыдущего вывода). Подсеть `192.168.0.0/24` не пересекается с вашей основной рабочей подсетью (предположительно `192.168.202.0/24`), конфликтов маршрутизации не возникнет.

**Как проверить результат:**
1. Выполните `/ip address print where interface=bridge1` и убедитесь, что новый адрес появился в списке со флагом `I` (invalid, если интерфейс выключен, но у вас он активен, так что флага не будет) или без флагов ошибок.
2. Выполните `ping 192.168.0.1` (адрес коммутатора SX3008F). Если пинг идёт, связь установлена.

**Риск:** Низкий. Операция не разрывает существующие TCP-сессии и не меняет правила фаервола.
**Идемпотентность:** Да. Если по ошибке запустить команду дважды, RouterOS выдаст сообщение `failure: already have such address` и не создаст дубликат, не нарушив работу системы.
**Откат:** Если по какой-то причине адрес нужно убрать, выполните:
```routeros
/ip address remove [find address=192.168.0.2/24]
```
**Уверенность:** Высокий. Это базовое, документированное поведение RouterOS.

**Объяснение / действие:**  
Отвечаю на ваши два вопроса напрямую, основываясь на принципах работы сетей TCP/IP и Ethernet:

1. **Что произойдет с IP-адресом?**  
   Второй MikroTik **не «перебьет»** первый и **не «не включится»**. Возникнет классический **IP-конфликт**. 2. **Сможете ли вы войти на него по MAC-адресу?**  
   **Да, сможете.** Утилита WinBox (а также MAC Telnet/SSH) работает на канальном уровне (Layer 2), используя протокол MikroTik Neighbor Discovery. Она обращается к устройству напрямую по его MAC-адресу, полностью игнорируя IP-стек и любые IP-конфликты.  
   *Условие:* Второй MikroTik должен быть подключен в тот же широковещательный домен (тот же VLAN/мост), что и ваш ноутбук, чтобы протокол обнаружения сработал.

Убедимся, что на устройстве нет лишних IP-адресов и VLAN-интерфейсов.
```routeros
/ip address print
/interface vlan print
/interface bridge port print
```

**Шаг 1.2 — Удаление лишних IP-адресов (если они есть)**
Если в выводе `ip address print` есть адреса, отличные от `192.168.200.3/22` на `bridge` (например, `192.168.0.2/24`), удалите их:
```routeros
/ip address remove [find address=192.168.0.2/24]
```
*(Если адресов несколько, команду нужно повторить для каждого или использовать `remove [find address!=192.168.200.3/22]`, но это рискованно, если есть другие нужные адреса).*

**Шаг 1.3 — Удаление лишних VLAN-интерфейсов (если они есть)**
Если в выводе `interface vlan print` есть интерфейсы (например, `vlan40-bridge`), удалите их:
```routeros
/interface vlan remove [find name=vlan40-bridge]
```

**Риск:** Низкий. Удаляются только явно лишние объекты.
**Идемпотентность:** НЕ идемпотентно (повторное удаление несуществующего объекта выдаст ошибку, но не навредит).
**Откат:** Ручное создание IP/VLAN заново.

### Вариант 2: Полный сброс к заводским настройкам

⚠️ **Риск: КРИТИЧЕСКИЙ.** Эта команда удалит **ВСЮ** конфигурацию устройства, включая IP-адреса, пароли, правила фаервола и настройки мостов. Устройство перезагрузится и будет как новое из коробки. Вы потеряете удаленный доступ, если не подключитесь физически через консоль или WinBox по MAC-адресу после сброса.

**Чек-лист перед выполнением:**
- [x] Вы понимаете, что все настройки будут удалены.
- [x] У вас есть физический доступ к устройству (кабель подключен к порту, который после сброса окажется в default-конфигурации, обычно `ether1` или `bridge`).
- [x] Вы готовы настраивать устройство заново.

**Команда для выполнения:**
```routeros
/system reset-configuration no-defaults=yes skip-backup=yes
```
*Параметры:*
- `no-defaults=yes` — сбросить к минимальной конфигурации (без демо-настроек).
- `skip-backup=yes` — не создавать резервную копию перед сбросом (ускоряет процесс).

После выполнения устройство перезагрузится.

**Идемпотентность:** НЕ идемпотентно (выполняется один раз).
**Откат:** Невозможен без ручной настройки или восстановления из бэкапа (если он был сделан ранее командой `/system backup save`).
