Шаг 2.1 — Проверка LLDP-соседей и полной ARP-таблицы моста

**Анализ вывода:**
1. **Хорошая новость:** MAC-адрес `58:04:4F:EE:25:92` **действительно присутствует** в таблице моста на порту `sfp11`. 2. **Проблема:** Несмотря на наличие на L2, устройство не отвечает на ARP-запросы и ICMP (ping). Это типично для двух случаев: 
   - IP-адрес управления коммутатора изменился и больше не `192.168.0.1`.
   - На коммутаторе TP-Link настроен фильтр, блокирующий ICMP и ARP-ответы на управление, но разрешающий служебный трафик.

Чтобы найти актуальный IP, мы используем протокол LLDP (стандартный способ обнаружения соседних сетевых устройств) и проверим всю ARP-таблицу моста на предмет нашего MAC-адреса.

*(Примечание: команда `stats` в предыдущем шаге завершилась ошибкой из-за синтаксиса, ниже дана корректная версия для просмотра счетчиков).*

1. Проверка соседей по протоколу LLDP (самый надежный способ узнать IP и имя коммутатора):
```routeros

```
*(Если команда выдаст ошибку `bad command name`, выполните альтернативу для старых версий RouterOS: `/interface lldp neighbor print`)*

2. Просмотр всей ARP-таблицы для моста `bridge` (чтобы найти наш MAC, если он привязан к другому IP):
```routeros
/ip arp print where interface=bridge
```

