   - **Realm**: `pve` (итоговое имя: `zabbix_monitor@pve`)

   - Нажмите **Add**.
2. Там же (**Permissions**) → кнопка **Add** → **User Permission**.

   - **Role**: `PVEAuditor` (встроенная роль только для чтения)

4. **Важно**: Скопируйте сгенерированный **Secret** (значение токена). Он отображается только один раз.

**Шаг 2.18 — Диагностика: проблема в Privilege Separation токена**

**Объяснение / действие**:  
Права пользователя `zabbix_monitor@pve` на `/nodes/pve01` назначены корректно (все необходимые привилегии есть). Но curl всё равно возвращает 403.

**Причина**: В Proxmox API-токены по умолчанию создаются с включённой **Privilege Separation** (`privsep=1`). Это означает, что токен имеет **свои собственные ACL**, которые пересекаются с ACL пользователя. Если для токена явно не назначены права, у него **нет доступа**, даже если у пользователя права есть.

**Действие 1: Проверить права токена**  
Выполните на pve01:
```bash
pveum user token permissions zabbix_monitor@pve zabbix_token
```

**Действие 2: Если у токена нет прав — два варианта решения**

**Вариант A (быстрый): Отключить Privilege Separation для токена**  
Токен будет использовать все права пользователя:
```bash
pveum user token modify zabbix_monitor@pve zabbix_token --privsep 0
```

**Вариант B (правильный для безопасности): Добавить ACL для токена**  
Назначить те же права, что и пользователю, но именно для токена:
```bash
pveum acl modify /nodes --token 'zabbix_monitor@pve!zabbix_token' --role Zabbix_Monitor
```

**Сверка с environment_facts**:  
- Пользователь: `zabbix_monitor@pve` — права есть ✅
- Токен: `zabbix_token` — вероятно, нет своих ACL ❌
- Роль `Zabbix_Monitor` содержит все нужные привилегии

**Как проверить результат**:  
После выполнения действия (A или B) повторите curl:


- Вариант B: Нет риска, более безопасный подход.

- Вариант A: Идемпотентно (можно выполнять многократно).
