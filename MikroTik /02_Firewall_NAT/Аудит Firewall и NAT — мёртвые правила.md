# Аудит Firewall и NAT: мёртвые правила

## Firewall Filter

### Цепочка INPUT

| # | Action | Условия | Статус |
|---|---|---|---|
| 0 | accept | in-interface=lo | ✅ OK |
| 1 | accept | protocol=icmp | ⚠️ ICMP с WAN проходит (не критично) |
| 2 | — | udp dst-port=1701,500,4500 | 🔴 **Нет action** — правило ничего не делает |
| 3 | — | protocol=ipsec-esp | 🔴 **Нет action** |
| 4 | — | protocol=ipsec-ah | 🔴 **Нет action** |
| 5 | accept | dst-address=192.168.199.1 | 🔴 **Legacy** — подсеть не маршрутизируется |
| 7 | accept | tcp dst-port=443,444 | ✅ OK |
| 8 | accept | connection-state=established,related | ✅ OK |
| 11 | drop | in-interface=pppoe-out1 | ✅ Ключевая защита WAN |
| 12 | drop | src-address=!192.168.0.0/16 | ✅ Доп. защита |
| 13 | drop | in-interface=sfp-sfpplus2 | ✅ Защита физ. WAN |

### Цепочка FORWARD

| # | Action | Условия | Статус |
|---|---|---|---|
| 9 | drop | src=192.168.199.0/24 dst=!192.168.0.0/16 | 🔴 **Legacy**, мёртвое (сеть не существует) |
| 10 | accept | (все) | ⚠️ **Крайне пермиссивно** |
| 14 | accept | src=192.168.200.7 dst=192.168.200.161 | 🔴 **Никогда не срабатывает** — стоит после #10 |
| 15 | reject | dst=192.168.200.161 | 🔴 **Никогда не срабатывает** — стоит после #10 |

### Цепочка OUTPUT
Правило #6 (`accept all`) — в порядке.

### Mangle / Raw / Address-list
Все три — **пусты**. Нет policy routing (mark-routing), нет QoS
(mark-packet), нет FastTrack/notrack. Весь трафик проходит через полный
stateful connection tracking — корректно для конфигурации такого размера,
но потенциально узкое место на PPPoE при высокой нагрузке (не измерялось).

**Итог по Filter:** 7 нерабочих правил — `#2, #3, #4, #5, #9, #14, #15`.

## NAT

### Srcnat
Правило `#0` (`masquerade`, `out-interface=pppoe-out1`) — в порядке, единственное.

### Dstnat (проброс портов)

| # | Внешний порт | Внутренний адрес:порт | Статус |
|---|---|---|---|
| 1 | TCP 443 | 192.168.1.3:443 | ✅ Рабочий |
| 2 | TCP 990 | 192.168.200.157:3389 | ⚠️ Рабочий, но без `in-interface` |
| 3 | TCP 13389 | 192.168.200.222:3389 | 🔴 **Legacy** (dst=192.168.199.1) |
| 4 | TCP 43389 | 192.168.200.157:3389 | 🔴 **Legacy** |
| 5 | TCP 23389 | 192.168.200.10:3389 | 🔴 **Legacy** |
| 6 | TCP 33389 | 192.168.200.152:3389 | 🔴 **Legacy** |
| 7 | TCP 53389 | 192.168.200.200:3389 | 🔴 **Legacy** |
| 8 | TCP 8555 | 192.168.1.10:8555 | ✅ Рабочий |
| 9 | TCP 8333 | 192.168.1.134:8333 | ✅ Рабочий |
| 10 | TCP 3432 | 192.168.200.10:8000 | ❌ **DISABLED** (не мёртвое, просто выключено осознанно?) |
| 11 | TCP 8777 | 192.168.1.170:8777 | ✅ Рабочий |
| 12 | TCP 8111 | 192.168.1.239:8111 | ✅ Рабочий |
| 13 | TCP 8000 | 192.168.1.98:8000 | ✅ Рабочий |

**Итог по NAT:** 5 мёртвых правил — `#3, #4, #5, #6, #7` (все с
`dst-address=192.168.199.1`). Правило `#10` отдельно — не мёртвое,
а выключенное (`DISABLED`); прежде чем удалять/включать, уточнить у
администратора назначение (проброс на `192.168.200.10:8000`, тот же
хост, что и рабочее правило `#5` из этой же таблицы указывало на разные
порты — возможно, замена одного правила другим, требует уточнения, не
предположения).

## Рекомендуемые команды очистки (НЕ выполнено, подготовлено для подтверждения)

```routeros
# Firewall Filter — удалить мёртвые правила
/ip firewall filter remove [find comment~"Allow L2TP/IPsec|Allow IPsec ESP|Allow IPsec AH|No internet for VPN clients|printer MU|pinter MU zapret"]
/ip firewall filter remove [find dst-address=192.168.199.1]

# NAT — удалить мёртвые правила
/ip firewall nat remove [find dst-address=192.168.199.1]

# Исправить порядок (после удаления #10-блокеров пересмотреть заново, не просто "передвинуть")
/ip firewall filter move [find comment~"printer MU|pinter MU zapret"] place-before=10
```
⚠️ Перед выполнением — проверить счётчики пакетов каждого правила
(`/ip firewall filter print stats`) и получить явное подтверждение
администратора на каждый блок удаления отдельно (не одной командой на
всё сразу) — согласно правилам «Подробного режима» исходного аудита.
