# ⚠️ Критические уязвимости MikroTik — план устранения (не применено)

**Статус: план подготовлен по итогам полного read-only аудита
(2026-09-19), администратор ещё не подтвердил переход к внесению
изменений.** Ни одна команда ниже не выполнена на устройстве.

## 🔴 CRITICAL

### 1. Службы управления без ограничения источника
`ssh` (22), `www` (80), `winbox` (8291) — включены без `allowed-addresses`.
```routeros
/ip service set ssh allowed-addresses=192.168.200.0/22,192.168.1.0/24,91.217.9.238/32
/ip service set www allowed-addresses=192.168.200.0/22,192.168.1.0/24
/ip service set winbox allowed-addresses=192.168.200.0/22,192.168.1.0/24,91.217.9.238/32
```
⚠️ **Риск потери доступа при неверном списке — проверить, с каких IP
реально подключается администратор, до выполнения.**

### 2. `mac-server` разрешён на всех интерфейсах
```routeros
/tool mac-server set allowed-interface-list=none
```
(или указать конкретный список доверенных интерфейсов вместо `none`, если управление по MAC нужно на LAN)

### 3. VPN-профиль ссылается на нерабочую подсеть
Подробности и команды — см. `NETWORK-MIKROTIK-VPN-PROFILE-BROKEN-2026-001`.

## 🟠 HIGH

### 4. Мёртвые правила Firewall (7 шт.) и NAT (5 шт.)
Подробности и команды — см. `NETWORK-MIKROTIK-FIREWALL-NAT-CLEANUP-2026-001`.

### 5. Порядок правил Filter (#14/#15 после accept-all #10)
```routeros
/ip firewall filter move [find comment~"printer MU|pinter MU zapret"] place-before=10
```
⚠️ Сначала решить (не в рамках этого документа), нужен ли вообще
`accept all` (#10) на forward — простая перестановка не убирает саму
пермиссивность.

### 6. Link flapping на `ether9`
Физическая проблема, не конфигурационная — подробности см.
`NETWORK-MIKROTIK-TOPOLOGY-2026-001`. Требует замены патч-корда/проверки
порта на месте, не команд RouterOS.

## 🟡 MEDIUM

### 7. Открытый DNS-резолвер и NTP-сервер
`allow-remote-requests=yes` для DNS, NTP-сервер включён. **Уточнение:**
WAN-доступ уже частично блокируется правилами Filter `#11`/`#13`
(`drop in-interface=pppoe-out1/sfp-sfpplus2`) — риск ниже, чем «полностью
открыто в интернет», но лучше отключить явно, если не должны быть
публичными.
```routeros
/ip dns set allow-remote-requests=no
/system ntp server set enabled=no
```

### 8. Отсутствует правило `drop invalid`
```routeros
/ip firewall filter add chain=input action=drop connection-state=invalid place-before=8
```

### 9. Слабая криптография SSTP
`pfs=no`, `tls-version=any`.
```routeros
/interface sstp-server server set pfs=yes tls-version=only-1.2;only-1.3
```
(точный синтаксис версии TLS сверить с версией RouterOS 7.23 перед выполнением)

## 🟢 LOW (опционально, не срочно)

10. Удалить неиспользуемые bridge-порты (`ether1`, `ether16-20` из `bridge_localnet`; `ether21`, `ether23` из `bridge_video`) — если точно не нужны.
11. Удалить `eoip-tunnel1` (disabled, не используется).
12. Завести отдельную учётную запись с группой `write` для повседневной работы, `admin` — только для критических изменений.

## Порядок внедрения
Подтверждено правило «Подробного режима» из исходного аудита: **один
логический шаг за раз, с подтверждением перед следующим**, начиная с
CRITICAL. Не выполнять несколько пунктов одной командой/сессией без
проверки между ними.
