# VPN-профиль ссылается на нерабочую подсеть

## Симптомы
VPN-серверы (L2TP/IPsec, SSTP) в статусе `enabled`, есть реальные
подключения от пользователей (например, `Gorelova` получает
`192.168.199.154`, `Brednev` — `192.168.199.151`) — то есть аутентификация
и установление туннеля проходят успешно. Но подключённые пользователи не
имеют рабочего доступа к сети `korona`.

## Диагностика

**PPP-профили:**

| Имя | Local-address | Remote-address (пул) | DNS | Кто использует |
|---|---|---|---|---|
| `default` | — (не задан) | — | — | **все 18 пользователей** |
| `vpn_profile` | `192.168.199.1` | `pool-vpn` | `255.255.255.255` | никто |
| `default-encryption` | — | — | — | не используется активно |

**Пул адресов `pool-vpn`:** `192.168.199.151–192.168.199.250` (100
адресов, 0 использовалось на момент явного запроса — но сессии в логе
показывают адреса именно из этого диапазона, то есть пул фактически
используется динамически через сам PPP-сервер, а не через явное
резервирование).

**Проверка маршрутизации подсети 192.168.199.0/24:**
```
/ip route print where dst-address~"192.168.199"
```
Результат — пусто. Подсеть `192.168.199.0/24` **нигде не
маршрутизируется** на устройстве (ни в `bridge_localnet`, ни в
`bridge_video`, ни отдельным маршрутом).

## Корневая причина
Два независимых дефекта конфигурации, оба нужно исправить:

1. **Все PPP-пользователи назначены на `profile=default`**, а не на
   `vpn_profile` — сам по себе `default` не задаёт `local-address`, из-за
   чего RouterOS откатывается к пулу `pool-vpn` (легаси, привязан к
   несуществующей сети `192.168.199.0/24`) как к запасному источнику
   адресов для PPP-соединений без явного профиля.
2. **`vpn_profile` (даже если бы использовался) сам по себе неисправен**:
   `local-address=192.168.199.1` (та же нерабочая подсеть) и
   `dns-server=255.255.255.255` — широковещательный адрес, не может быть
   валидным DNS-сервером ни при каких обстоятельствах.

## Решение (подготовлено, НЕ применено)

**Шаг 1 — исправить сам профиль `vpn_profile`:**
```routeros
/ppp profile set vpn_profile local-address=192.168.200.1 dns-server=192.168.200.1
```
(Как вариант вместо `192.168.200.1` — публичный DNS `8.8.8.8`, если
клиентам не нужен доступ к внутреннему DNS `krnn.ru`.)

**Шаг 2 — перевести пользователей на исправленный профиль (только после Шага 1):**
```routeros
/ppp secret set [find] profile=vpn_profile
```
⚠️ Затронет всех 18 пользователей разом — рекомендуется сначала
применить к 1-2 тестовым учётным записям, подтвердить рабочий доступ,
потом перевести остальных.

## Проверка результата (после применения — критерии)
- [ ] Новое подключение получает адрес из диапазона `192.168.200.x` (или другого реально маршрутизируемого), не `192.168.199.x`.
- [ ] Клиент резолвит DNS-имена внутренней сети (`nslookup ad.krnn.ru` или аналог).
- [ ] Клиент имеет доступ к внутренним ресурсам (ping/RDP/etc. по назначению).
